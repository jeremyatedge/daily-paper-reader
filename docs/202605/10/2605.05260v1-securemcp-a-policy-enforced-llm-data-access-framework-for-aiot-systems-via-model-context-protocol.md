## 摘要
在智能物联网（AIoT）系统中部署大语言模型（LLM）生成的 SQL 查询会引入关键的安全风险，因为提示词注入攻击可以操纵 LLM 生成未经授权的查询，从而暴露敏感数据或执行破坏性操作。现有的 NL2SQL 研究侧重于查询准确性，而 MCP 服务器实现仅提供 SQL 级别的保护，缺乏细粒度的基于角色的访问控制（RBAC）。本文提出了 SecureMCP，这是一种策略强化的 LLM 数据访问框架，它将基于角色的访问控制（RBAC）与 MCP 服务器集成，为 LLM 生成的 SQL 执行建立多层防御。该框架包含五个防御模块：用于表级和列级 RBAC 的 check_policy、用于阻断高开销查询的 explain_gate、用于危险模式检测的 SQL 拦截器（SQL Interceptor）、用于 SQL 风险分类的风险等级过滤器（Risk Level Filter）以及用于跨数据库限制的数据库隔离（DB Isolation）。这些模块在一个顺序的“故障关闭”（fail-closed）流水线中运行，并映射到基于 OWASP LLM 应用十大安全风险的六种提示词注入类型。我们在 IoT-SQL 数据集（包含 11 张表、173 列、239,398 条记录）上使用 Qwen3-8B 对 SecureMCP 进行了评估。实验 A 表明，防御模块保持了执行准确性，在四种 RBAC 角色中，EX-in-ALLOW 保持在 65.1%-76.4% 之间，与 63.8% 的无保护基准线相当。实验 B 显示，SecureMCP 在 2,400 个对抗性查询中实现了 82.3% 的策略合规性，真实的防御失败率仅为 3.4%。纵深防御分析显示，check_policy 占据了 78.7% 的拦截量，而辅助模块额外贡献了 17.5 个百分点的提升。72.5% 的注入合并率（Injection Incorporation Rate）证实了 LLM 的高易感性，确立了外部策略强制执行的必要性。

## Abstract
The deployment of Large Language Model (LLM)-generated SQL queries in Artificial Intelligence of Things (AIoT) systems introduces critical security risks, as prompt injection attacks can manipulate LLMs into producing unauthorized queries that expose sensitive data or execute destructive operations. Existing NL2SQL research focuses on query accuracy, while MCP server implementations provide only SQL-level protections without fine-grained role-based access control. This paper proposes SecureMCP, a policy-enforced LLM data access framework integrating Role-Based Access Control (RBAC) with an MCP server to establish multi-layer defense for LLM-generated SQL execution. The framework incorporates five defense modules -- check_policy for table-and-column-level RBAC, explain_gate for cost-explosive query blocking, SQL Interceptor for dangerous pattern detection, Risk Level Filter for SQL risk classification, and DB Isolation for cross-database restriction -- operating in a sequential fail-closed pipeline mapped to six prompt injection types grounded in the OWASP Top 10 for LLM Applications. We evaluate SecureMCP on the IoT-SQL dataset (11 tables, 173 columns, 239,398 records) using Qwen3-8B. Experiment A demonstrates that defense modules preserve execution accuracy, with EX-in-ALLOW remaining within 65.1%-76.4% across four RBAC roles, matching the unprotected baseline of 63.8%. Experiment B shows that SecureMCP achieves 82.3% Policy Compliance on 2,400 adversarial queries, with genuine defense failures limited to 3.4%. The defense-in-depth analysis reveals check_policy accounts for 78.7% of blocks, while secondary modules contribute an additional 17.5 percentage-point improvement. The Injection Incorporation Rate of 72.5% confirms high LLM susceptibility, establishing the necessity of external policy enforcement.

### 论文总结：SecureMCP — 基于策略强化的 AIoT 系统 LLM 数据访问框架

#### 1. 核心问题与整体含义（研究动机和背景）
随着 AIoT（智能物联网）系统的普及，非专业人员通过大语言模型（LLM）以自然语言查询数据库（NL2SQL）的需求日益增长。然而，现有的 NL2SQL 研究大多集中在**查询准确性**上，忽视了**执行阶段的安全性**。
*   **安全风险**：提示词注入（Prompt Injection）可能诱导 LLM 生成未经授权的 SQL，导致敏感数据泄露（如 IP/MAC 地址）、系统可用性下降（高开销查询）或数据破坏（DDL 操作）。
*   **技术缺口**：现有的模型上下文协议（MCP）服务器虽有基础防护，但缺乏细粒度的基于角色的访问控制（RBAC）。
*   **研究目标**：在 AIoT 环境下，构建一个既能保证查询准确性，又能强制执行安全策略的多层防御框架。

#### 2. 方法论：核心思想与关键技术
论文提出了 **SecureMCP** 框架，其核心思想是在 LLM 生成 SQL 与数据库执行之间插入一个**策略强化层**。该框架采用“纵深防御”架构，包含五个顺序执行的防御模块：
*   **check_policy (RBAC 引擎)**：核心模块。通过解析 SQL 抽象语法树（AST），对比预设的“角色-权限矩阵”，在表级和列级拦截越权操作。
*   **explain_gate (成本验证)**：利用 MySQL 的 `EXPLAIN` 命令预估扫描行数，若超过阈值（如 500,000 行）则阻断，防止拒绝服务（DoS）攻击。
*   **SQL Interceptor (模式拦截)**：基于正则表达式识别危险模式（如 `UNION SELECT`、`LOAD_FILE`、`SLEEP` 等）。
*   **Risk Level Filter (风险等级过滤)**：将 SQL 分为低、中、高、危四个等级，生产环境仅允许低风险（简单 SELECT）操作。
*   **DB Isolation (数据库隔离)**：强制限制访问范围，禁止跨库查询或访问系统元数据表。
*   **工作流程**：采用 **Fail-closed（故障关闭）** 逻辑，SQL 必须通过全部五个模块的校验才能执行。

#### 3. 实验设计
*   **数据集**：使用 **IoT-SQL** 数据集，包含 11 张表、173 个列、约 24 万条记录，涵盖网络流量日志和智能建筑传感器数据。
*   **场景设置**：定义了四种角色（网络管理员、传感器工程师、设施经理、审计员），权限依次递减。
*   **Benchmark 与对比**：
    *   **Pipeline A (NL2SQL)**：基准线，LLM 生成 SQL 后直接执行，无保护。

*   **测试集**：1,900 个干净查询（用于测准确性）和 2,400 个对抗性注入查询（涵盖 6 种 OWASP 注入类型）。

#### 4. 资源与算力
*   **硬件**：使用单张 **NVIDIA A6000 (48 GB VRAM)** GPU，配备 16 核 CPU 和 64 GB RAM。
*   **软件/模型**：使用 **Qwen3-8B-FP8** 模型，通过 **vLLM 0.8** 进行推理部署。
*   **训练时长**：论文未提及模型训练时长，因为实验主要基于现成模型的推理和外部防御框架的评估。

#### 5. 实验数量与充分性
*   **实验规模**：总计进行了约 **14,300 次** 查询测试（包括不同角色下的干净查询和各类注入攻击）。
*   **充分性**：实验设计较为全面。通过“实验 A”验证了防御机制对正常业务的**透明性**（不干扰合法查询）；通过“实验 B”验证了对 6 种不同注入攻击的**鲁棒性**。
*   **客观性**：引入了“注入合并率”（Incorp）和“真实防御失败率”等细分指标，区分了“模型自身抗性”与“防御框架有效性”，评价标准较为客观。

#### 6. 主要结论与发现
*   **防御不降准**：在合法查询中，SecureMCP 的执行准确率（EX-in-ALLOW）保持在 65.1%-76.4%，与无保护基准（63.8%）相当，证明安全层不会误伤合法业务。
*   **高效拦截**：在 2,400 个恶意查询中实现了 **82.3% 的策略合规率**，其中 `check_policy` 拦截了 78.7% 的攻击，体现了 RBAC 的核心地位。
*   **LLM 易受攻击**：Qwen3-8B 的注入合并率高达 **72.5%**，证明仅靠模型自身的“对齐”或“鲁棒性”无法保障 AIoT 数据库安全。
*   **纵深防御价值**：辅助模块（如 SQL 拦截器）在 RBAC 之外额外提升了 17.5% 的拦截率，证明了多层架构的必要性。

#### 7. 优点（亮点）
*   **架构创新**：首次将新兴的 **MCP 协议** 与传统的 **RBAC** 结合，解决了 LLM 插件/工具调用的细粒度权限控制问题。
*   **威胁建模科学**：防御模块与 **OWASP Top 10 for LLM** 风险一一对应，具有很强的实战指导意义。
*   **AIoT 针对性**：实验基于真实的物联网安全数据集，考虑了 IP/MAC 等敏感字段的特殊保护需求。

#### 8. 不足与局限
*   **模型单一性**：仅测试了 Qwen3-8B，未在 GPT-4 或 Llama-3 等其他主流模型上验证通用性。
*   **规则依赖**：防御主要基于规则和正则，对于高度混淆或利用逻辑漏洞的复杂注入攻击，可能存在绕过风险。
*   **成本阈值粗糙**：`explain_gate` 使用全局统一的行数阈值，未考虑不同表规模的差异（论文中提到这是导致 INJ-4 类型攻击漏报的主因）。
*   **解析性能**：对于极其复杂的嵌套子查询，SQL 解析器可能存在解析偏差，导致误报或漏报。
