## 摘要
大语言模型（LLM）推理在边缘 AI 系统上的部署日益增多，要求在紧张的内存预算下实现高效执行。一个关键挑战源于键值（KV）缓存，其大小通常超过了可用的设备内存。尽管基于 NVMe 的卸载提供了可扩展的容量，但现有的基于文件的设计严重依赖内核页面缓存（page cache），导致在内存压力下出现缓存抖动、不可预测的延迟以及高昂的软件开销。我们提出了 DUAL-BLADE，这是一个双路径 KV 驻留框架，可根据运行时内存可用性动态地将 KV 张量分配到页面缓存路径或 NVMe 直连路径。NVMe 直连路径通过将 KV 张量映射到连续的逻辑块地址（LBA）区域来绕过文件系统，从而实现低开销的直接存储访问。DUAL-BLADE 进一步结合了自适应流水线并行，使存储 I/O 与 GPU DMA 重叠，从而提高推理吞吐量。我们的评估表明，DUAL-BLADE 显著缓解了 I/O 瓶颈，在不同内存预算下，将预填充（prefill）和解码（decode）延迟分别降低了高达 33.1% 和 42.4%，同时将 SSD 利用率提高了 2.2 倍。

## Abstract
The increasing deployment of Large Language Model (LLM) inference on edge AI systems demands efficient execution under tight memory budgets. A key challenge arises from Key-Value (KV) caches, which often exceed available device memory. Although NVMe-based offloading offers scalable capacity, existing file-based designs rely heavily on the kernel page cache, leading to cache thrashing, unpredictable latency, and high software overhead under memory pressure. We present DUAL-BLADE, a dual-path KV residency framework that dynamically assigns KV tensors to either a page-cache path or an NVMe-direct path based on runtime memory availability. The NVMe-direct path bypasses the filesystem by mapping KV tensors to contiguous logical block address (LBA) regions, enabling low-overhead direct storage access. DUAL-BLADE further incorporates adaptive pipeline parallelism to overlap storage I/O with GPU DMA, improving inference throughput. Our evaluation shows that DUAL-BLADE substantially mitigates I/O bottlenecks, reducing prefill and decode latency by up to 33.1% and 42.4%, respectively, while improving SSD utilization by 2.2x across diverse memory budgets.

### 论文总结：DUAL-BLADE 面向边缘大模型推理的双路径 NVMe 直连 KV 缓存卸载

#### 1. 核心问题与整体含义（研究动机和背景）
在边缘 AI 系统（如本地服务器或嵌入式设备）上部署大语言模型（LLM）时，内存资源极其有限（通常仅 8-32GB DRAM）。LLM 推理过程中产生的 **KV 缓存（Key-Value Cache）** 随上下文长度和 Batch Size 增加而迅速膨胀，往往会耗尽 GPU 显存并溢出到主机内存。
现有的卸载（Offloading）方案（如 FlexGen）通常依赖操作系统的**页面缓存（Page Cache）**和文件映射（`mmap`）。然而，这种方式在边缘场景下存在三大瓶颈：
*   **页面缓存抖动（Thrashing）：** LLM 解码阶段的自回归访问模式与操作系统的 LRU 替换策略冲突，导致缓存命中率骤降。
*   **内核软件栈开销：** 经过 VFS、文件系统和块层的传统 I/O 路径延迟高，无法发挥 NVMe SSD 的性能。
*   **顺序性破坏：** 内核的多队列块层会将原本连续的 KV 流打散，降低了 SSD 控制器的效率。

#### 2. 方法论：核心思想与关键技术
DUAL-BLADE 提出了一个双路径 KV 驻留框架，核心思想是**根据内存预算动态分流 KV 张量**，并绕过内核存储栈。
*   **双路径 KV 驻留（Dual-Path KV Residency）：** 系统动态评估可用页面缓存预算（$B_{pc}$）。将一部分 KV 张量分配给“页面缓存路径”（Group 1），利用剩余 DRAM 提升速度；将其余张量分配给“NVMe 直连路径”（Group 2），直接存储在 SSD 的逻辑块地址（LBA）中。
*   **NVMe 直连与顺序 LBA 放置：** 针对 Group 2，利用 `io_uring_cmd` 绕过文件系统和内核块层。通过预先计算张量大小，将 KV 张量映射到连续的 LBA 区域，确保在 SSD 硬件层面实现纯顺序访问。
*   **自适应流水线并行（Adaptive Pipeline Parallelism）：** 为了掩盖 I/O 延迟，设计了两种重叠策略：
    *   **Overlap-Intra：** 并行化存储读取。
    *   **Overlap-Cross：** 通过“交错启动（Staggered Start）”使存储 I/O 与 GPU DMA 传输重叠。系统在运行时自动分析吞吐量并选择最优策略。
