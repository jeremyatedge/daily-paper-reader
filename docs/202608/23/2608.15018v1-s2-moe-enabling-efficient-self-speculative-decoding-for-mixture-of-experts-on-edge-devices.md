## 摘要
由于严重的内存和带宽限制，在边缘设备上部署大语言模型（LLM）进行推理具有挑战性。虽然推测解码和混合专家模型（MoE）已被提出以提高推理效率，但简单地将它们组合往往会带来过多的验证开销和较差的专家重用，限制了它们在内存受限边缘场景中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提高验证效率，并通过共享上下文对齐草稿和目标执行。在llama.cpp中实现，S2-MoE在边缘设备上的多样化MoE模型和数据集上，相比标准自回归解码实现了高达5.3倍的加速（平均约2.0倍）。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama.cpp, S2-MoE achieves up to 5.3x speedup (about 2.0x on average) over standard autoregressive de?coding across diverse MoE models and datasets on edge devices.Code is available at https://github.com/angerybob/S2-MoE.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：大语言模型（LLM）在边缘设备上的部署受限于内存带宽与存储容量，推理吞吐率由“输出密度”（每迭代生成 token 数）和“参数密度”（每迭代访问参数量）共同决定。
- **核心问题**：投机解码（Speculative Decoding, SD）和混合专家模型（MoE）虽然有互补优势，但直接组合在边缘场景存在三重矛盾：
  1. **冗余验证开销高**：MoE 模型为每个草稿 token 激活不同专家，被拒绝的 token 会造成大量无效参数访问；
  2. **专家参数复用差**：并行验证时相邻 token 往往触发不同的专家集合，难以像稠密模型那样共享参数；
  3. **轻量草稿保真度不足**：现有自推测解码的草稿模型与目标模型之间上下文不一致，导致误差随解码步长累积，接受率下降。
- **整体含义**：现有 SD 方法在 MoE 边缘推理中常常收益有限甚至退化为负加速，需要一种同时兼顾草稿保真度、验证开销和专家复用性的专用框架。

## 2. 方法论：S2-MoE 的核心思想与关键技术

S2-MoE 采用“自推测解码”路线，从目标模型自身构造轻量草稿，并围绕 MoE 特性设计了三个互补组件：

### 2.1 路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）
- **动机**：MoE 中 token 级置信度无法反映专家级验证成本，两个置信度相似的候选 token 可能触发完全不同的专家激活集合，导致验证开销差异悬殊。
- **核心机制**：
  - 对候选 token \(i\)，定义期望收益 \(B_i = p_i \cdot T_{\text{AR}}\)，其中 \(p_i\) 为前缀累积置信度，\(T_{\text{AR}}\) 为一步目标模型解码延迟；
  - 定义边际验证成本：
    \[
    \Delta C_{\text{ver}}(i|S) = |E_i \setminus \bigcup_{j \in S} E_j| \cdot T_{\text{exp}}
    \]
    即 token \(i\) 新引入的专家数量乘以单位专家激活延迟；
  - 效用函数 \(U_i = B_i / (\Delta C_{\text{ver}}(i|S) + C_i^{\text{draft}})\)，贪心扩展仅保留 \(U_i \ge 1\) 的候选节点。
- **效果**：与固定宽度扩展或单纯置信度剪枝相比，该方法在相同接受长度下显著降低验证成本，将“接受-验证”的帕累托前沿推向更优。

### 2.2 复用感知专家门控（Reuse-aware Expert Gating）
- **动机**：MoE 中相邻 token 的专家选择离散且分散，并行验证时参数复用率很低。
- **核心机制**：
  1. 以 token 置信度为权重，将同一 MoE 层内多个草稿 token 的专家 logits 聚合为全局专家重要性 \(g_e = \sum_b w_b \ell_{b,e}\)；
  2. 选取“全局优先专家集合” \(E^*\)（受容量 cap 约束，保证原始 top-\(k\) 专家仍可被选中）；
  3. 对草稿 token 的 gating logits 施加软性偏置：\(\ell'_{b,e} = \ell_{b,e} + \lambda_b \cdot \mathbb{1}[e \in E^*]\)，其中 \(\lambda_b\) 由 token 自身 top-1 与第 \(k+1\) 个专家的分数间距决定。
- **效果**：低置信度 token 更可能被引导到已激活的专家，从而提升跨 token 专家复用，同时几乎不改变高置信度 token 的原始选择；实现方式为轻量级融合 CUDA kernel，开销可忽略。

### 2.3 上下文对齐自推测解码（Context-aligned Self-speculative Decoding）
- **动机**：草稿模型若维护独立上下文，其预测误差会逐轮累积，导致与目标模型分布发散（KL 散度随步长增长）。
- **核心机制**：草稿与目标模型共享同一 KV Cache；草稿产生 KV 更新仅临时生效，验证前回滚，只有被接受的 token 才提交到共享缓存。
- **效果**：误差被限制在单个推测步内，不跨迭代传播，使轻量草稿的接受率显著提升，且不破坏最终输出正确性。

### 2.4 系统实现
- 基于 **llama.cpp** 实现；
- 针对边缘内存约束实现了 **专家级参数卸载**（expert-level offloading），非专家参数常驻设备内存，冷专家按需从 SSD 或 CPU 内存加载；
- 支持在 Jetson Orin（统一 DRAM）与 RTX 4090（分立 CPU/GPU 内存）两种平台上运行。

- 在 Jetson Orin 上实现 **1.3×–5.3×** 加速（平均约 2.0×），在 RTX 4090 上实现 **1.2×–2.9×** 加速，且稳定优于所有对比 baseline。

- **训练无关、部署友好**：无需额外训练草稿模型，只需轻量 profiling 和 fuse kernel，适合边缘设备；完整集成到 llama.cpp 并开源代码，可复现性强。

## 8. 不足与局限

- **对比 baseline 不对称**：LS（层稀疏）未在 Qwen3/GPT-OSS 上评测；Cascade 全部叠加在 EAGLE3 上，可能无法完全代表其独立方法的最佳表现；EAGLE3 在不同模型上的效果方差较大，给“公平比较”带来一定挑战。

- **未讨论真实边缘部署中更多变量**：如电量消耗、热降频、CPU-GPU 数据拷贝延迟、iOS/Android 等更碎片化平台，可能在真实应用中有额外开销。
- **成本模型依赖离线 profiling**：单位专家延迟 \(T_{\text{exp}}\) 和目标解码延迟 \(T_{\text{AR}}\) 需要针对硬件和内存预算提前标定，动态变化的工作负载可能降低估计精度。
- **对 MoE 门控的软偏置是近似方法**：虽然实验显示质量损失很小，但在某些分布外或长尾路由模式下，可能对低置信度 token 的生成质量产生未知影响。
