## 摘要
对延迟敏感的边缘AI服务必须在严格的截止时间、输出质量以及有限的计算和能源预算之间取得平衡。然而，静态CPU配置会浪费资源，因为推理成本在不同输入、模型变体和运行条件下差异很大。我们提出了PRISM，一个预测引导的运行时框架，它为容器化边缘微服务联合选择模型变体和CPU分配。通过使用容器级能量监控和轻量级回归模型，PRISM就地调整每个流水线阶段，并在截止时间、资源和离线模型级结果质量（QoR）约束下最小化预测的CPU封装能耗。我们在一个具有检测和识别阶段的自动车牌识别（ALPR）流水线上对超过52,000个请求进行了PRISM评估。对于检测，与最强的静态配置相比，PRISM在保持相当成功率的同时降低了36%的能耗，并且平均CPU分配不到其一半。对于识别，它以较低的平均CPU分配达到了接近静态最优的性能。这些结果表明，预测式就地适应是使对时间敏感的AI微服务流水线在边缘更节能的一种实用机制。

## Abstract
Latency-sensitive edge AI services must balance strict deadlines, output quality, and limited compute and energy budgets. However, static CPU provisioning wastes resources because inference cost varies substantially across inputs, model variants, and runtime conditions. We present PRISM, a prediction-guided runtime framework that jointly selects model variants and CPU allocations for containerized edge microservices. Using container-level energy monitoring and lightweight regression models, PRISM adapts each pipeline stage in place and minimizes predicted CPU-package energy under deadline, resource, and offline model-level Quality of Result (QoR) constraints. We evaluate PRISM on more than 52,000 requests in an Automatic License Plate Recognition (ALPR) pipeline with detection and recognition stages. For detection, PRISM reduces energy consumption by 36 % compared to the strongest static configuration while preserving a comparable success rate and using less than half of the average CPU allocation. For recognition, it reaches near-static-best performance with lower average CPU allocation. These results show that predictive in-place adaptation is a practical mechanism for making time-sensitive AI microservice pipelines more energy-efficient at the edge.

## 论文总结

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：边缘AI服务（如自动车牌识别ALPR）必须在严格的截止时间（deadline）、输出质量（QoR）和有限的计算/能源预算之间取得平衡。传统的静态CPU资源配置方式无法应对推理成本在不同输入、模型变体和运行时条件下的巨大差异，导致资源浪费或服务质量不达标。
- **研究背景**：
  - 边缘计算将计算推向数据源附近，但AI工作负载在资源受限设备上运行，对延迟和能耗高度敏感。
  - 近似计算（Approximate Computing）领域已广泛研究"质量-时间-能耗"的权衡，但如何在容器化微服务中实际落地这一权衡仍缺乏系统性的运行时机制。
  - 已有工作（如MARQ）在服务链级别进行路径选择，但假设每个微服务阶段的资源分配在执行期间固定不变，未解决"**每个阶段如何按请求选择模型变体和CPU分配**"的问题。
- **整体含义**：PRISM的核心洞见是——通过**轻量级预测模型**在请求到达前估计各配置（模型×CPU）的执行时间和能耗，并**在每个微服务阶段就地（in-place）应用最优选择**，可以在满足截止时间和质量约束的前提下显著降低能耗，从而实现"按需供给"的精细化资源管理。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：PRISM是一个预测引导的运行时框架，对每个传入请求和每个微服务阶段，枚举所有（模型变体 m、CPU分配 c）组合，筛选满足QoR和deadline约束的候选，并选择预测能耗最小的配置，通过Kubernetes的就地垂直扩缩机制（In-Place Pod Resize）实时应用，无需重启Pod。
- **系统架构（闭环控制回路）**：
  1. **测量子系统**：基于Kepler，将Intel RAPL的CPU封装能耗计数归因到容器级别，通过请求前后采样差值得到每请求的CPU封装能耗和运行时间。
  2. **离线预处理**：将测量轨迹转为特征向量（模型、CPU分配、图像宽高、文件大小），训练回归模型。
  3. **运行时决策**：对每个候选配置预测时间和能耗，过滤不可行项，选择能耗最小的配置。
  4. **就地执行**：通过kubelet修改cgroup CPU限制（不重启Pod），模型切换在进程内完成（所有权重预加载）。
- **特征构造**：
  - 特征向量 z(m, c, h, w, b) = [m, c, h, w, b]，其中 m 为模型（one-hot编码），c 为CPU分配，h/w/b 为图像高度/宽度/文件大小。
  - QoR不作为特征（在线无ground truth），而是作为**离线模型级质量约束**。
  - 多项式基线使用 φ(z) = [φ_d(c), φ_d(h), φ_d(w), φ_d(b), OHE(m)]。
- **预测模型**：
  - 候选回归器：线性回归、多项式回归（Poly-2/3）、贝叶斯回归、MLP、XGBoost。
  - XGBoost在实验中表现最优（MAPE最低），被选为默认预测器。
  - 贝叶斯回归提供可信区间半宽 ΔT，支持**保守deadline检查**（bT + ΔT ≤ T_max）；XGBoost使用验证残差的95百分位数作为经验松弛。
- **决策问题形式化**（每阶段k）：
  - 目标：min bE_k(m, c)
  - 约束：bT_k(m, c) + ΔT_k(m, c) ≤ T_max^k（截止时间）；QoR_m ≥ QoR_min^k（质量）；c ≤ C_rem（资源预算）
- **算法流程（Algorithm 1）**：
  1. 提取输入图像属性 (h, w, b)。
  2. 按流水线顺序，对每个阶段 k：
     - 枚举所有满足QoR和资源约束的 (m, c) 组合；
     - 构建预处理向量，调用预测器得到 (bE, bT, ΔT)；
     - 过滤deadline不可行的候选；
     - 从剩余候选中选择 bE 最小的配置并就地应用；
     - 若无可选配置，返回FALLBACK（记录失败）。
  3. 执行完当前阶段后将实际输出（如OCR裁剪区域）传递给下一阶段，替代预估的bucket值。
- **多阶段依赖处理**：OCR阶段的输入（检测crop）在DETECT执行前不可知，通过**分桶估计**（基于训练数据中该分辨率下的典型crop尺寸）作为预执行特征，实际crop产生后立即替换。
- **实现细节**：Java微服务链中，预处理管道通过ONNX导出，XGBoost模型通过ONNX Runtime加载；Timefold实现局部搜索求解（Hill Climbing，可提前终止），但作者指出**直接枚举**在候选空间有限（检测20个、OCR 32个）时更优。

### 6. 论文的主要结论与发现

- **RQ1（预测基础）**：垂直CPU缩放显著减少执行时间，但效果因输入分辨率和模型架构而异；能耗通常随运行时间减少而下降，但在高分辨率下收益递减，且可能非单调。XGBoost在所有预测器中表现最优（DETECT时间MAPE 2.6%、能耗4.7%；OCR时间6.4%、能耗5.5%），说明这些效应可从轻量级特征准确预测。
- **RQ2（运行可行性）**：XGBoost+Timefold的决策开销中位数为DETECT推理时长的30.5%、OCR的16.2%（95百分位为59.2%/42.4%），低于推理时延但不可忽略；MLP预测器开销降到0.6%以下但预测精度下降，存在预测质量与决策延迟的权衡。冷启动效应阶段依赖：DETECT首请求耗时和能耗达暖机中位数2.3×/3.0×，OCR几乎无冷启动影响。
- **RQ3（流水线执行）**：
  - **DETECT阶段**：PRISM+XGBoost达到85.7%成功率、551.1 kJ总能耗、平均2.4核，相比最强静态配置（RT-DETRx/5 CPU：84.5%/859.9 kJ/5核），**能耗降低35.9%，成功率相当，平均CPU分配不到一半**。
  - **OCR阶段**：PRISM+XGBoost达到91.0%成功率、21.5 kJ，以0.6核平均分配匹配并略超最强静态配置（PaddleOCRv4/1.5核：90.2%/21.8 kJ）。动态增益较小，因为OCR静态配置本身已接近最优。
  - 动态选择在静态设计空间"存在大量廉价但不可行、昂贵但可靠的配置"时收益最大，这一条件在DETECT中明显，在OCR中较弱。
- **总体结论**：预测引导的就地适应是一种实用机制，可在满足截止时间和质量约束的同时显著提升边缘AI微服务流水线的能效。

### 7. 优点：方法或实验设计上的亮点

- **完整性**：实现了从监测→预处理→训练→预测→决策→执行→反馈的完整闭环，技术栈均基于成熟开源工具（Kepler、Kubernetes、ONNX），可部署性强。
- **机制创新**：将QoR明确作为阶段级运行时约束（而非全局目标），使用离线模型级QoR分数，避免了在线ground truth依赖，使决策可复现且部署无关。
- **精确的能量建模**：使用CPU封装能耗（RAPL）而非系统总能耗，聚焦决策可控制的成本分量，提高信号灵敏度；Kepler容器级归因使按请求能量核算成为可能。
- **多阶段依赖的巧妙处理**：通过分桶估计解决下游阶段输入依赖问题，并在上游执行后用实际尺寸替换估计值。
- **实验设计严谨性**：RQ结构清晰（从预测基础→运行可行性→端到端效果），报告IQR和中位数降低噪声影响，包括失败请求在内的能耗统计避免了"幸存者偏差"。
- **可泛化论证**：UFPR-ALPR作为"分布外"测试集验证了模型对不同数据分布的泛化能力；延迟-质量-能耗权衡框架不限于ALPR。

### 8. 不足与局限：实验覆盖、偏差风险、应用限制

- **QoR粒度局限**：离线模型级QoR无法保证每请求的实际质量（输入难度、分布漂移未被捕获）。作者承认应结合在线校准信号（如置信度、时间一致性）。
- **能耗范围局限**：仅优化CPU封装能耗，忽略DRAM、存储、网络、空闲基线等全系统能量成分。这些成分虽不受CPU分配直接影响，但在完整能量核算中可能显著。
- **模型预加载假设**：所有候选模型需常驻内存，在内存受限的边缘设备上可能不适用；模型加载/驱逐/放置的生命周期管理不在PRISM范围内。
- **决策开销**：XGBoost+Timefold实现的开销较大（可达推理时长的59%），虽然低于推理时长且可用直接枚举消除，但在超低延迟场景下仍需优化。
- **实验硬件单一**：仅Intel x86平台，未验证ARM等常见边缘平台；RAPL依赖Intel平台的适用性存在局限。
- **无消融实验**：未隔离分析"单用模型选择"vs"单用CPU缩放"vs"两者联合"的贡献，组件级效果难以单独归因。
- **缺少跨流水线优化**：PRISM不涉及跨阶段deadline预算重新分配、全局调度或竞争资源协调，限制了在复杂多流水线场景的优化上限。
