## 摘要
我们提出ELMOD——用于设备端部署的高效语言模型——一个紧凑的（2.7B）德语语言模型，专为在资源受限硬件上进行高效推理而设计。ELMOD在有限的计算预算（55k H100 GPU小时）下，仅使用公开可用的数据进行训练。我们开发了一套针对德语的数据预处理方法，与面向英语的方法不同，这些方法在处理形态变化、复合词和拼写惯例方面有所区别。此外，我们引入了质量过滤和改写步骤，提高了数据的教学/指导质量，提升了退火阶段的性能，并降低了整体计算需求。得益于我们的架构模型和数据选择，包括预过滤、教育质量过滤和改写以提高教育质量，ELMOD是其尺寸类别（<3B）中表现最强的模型，在德语上匹配7B参数模型的性能。

## Abstract
We present ELMOD - Efficient Language Model for On-Device Deployment - a compact (2.7B) German language model designed for efficient inference on resource-constrained hardware. ELMOD was trained on a limited computational budget (55k H100 GPU hours) using exclusively publicly available data. We developed a suite of German-specific data pre-processing, which differ from English-oriented counterparts in their handling of morphological variation, compounding, and orthographic conventions. Furthermore, we introduced a quality filtering and rephrasing step, which increased the instructional quality of the data, improved performance during the annealing phase, and reduced overall compute requirements. Thanks to our architectural model and data choices, including prefiltering, our educational-quality filtering and rephrasal to raise the educational-quality, ELMOD is the strongest performer in its size class (<3B), matching the performance of 7B-parameter models in German.

- **整体含义**：论文旨在展示如何在有限计算预算（55k H100 GPU小时）下，仅使用公开数据，从数据采集、预处理、训练到端侧部署，构建一个紧凑（2.7B）但性能强劲的德语优先语言模型，为德语NLP的本地化、低资源部署提供可复现的方法论。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 总体流程
模型构建分为三大阶段：数据准备 → 预训练 → 后训练/部署（论文Figure 1给出全流程概览）。

### 2.1 数据准备（Data Preparation）
- **数据来源**：训练数据配比为45%德语、45%英语、10%代码。
  - 德语数据：来自Common Crawl原始转储（截至2025年3月快照，总计4.83T词）。
  - 英语数据：DCLM（DataComp-LM随机子集）。
  - 代码数据：CodeParrot清洗版（覆盖30种编程语言）。
- **多级过滤管道**（按计算成本从低到高排序，以尽早剔除无用数据）：
  1. **语言过滤**：使用Resiliparse提供的语言标签筛选德语内容。
  2. **行过滤（Line Filter）**：基于C4方法调整德语版，丢弃纯数字/大写行、重复行、含特定关键词过多的行，并采用序列移除处理短重复序列。
  3. **文档过滤（Document Filter）**：受Gopher/MassiveText启发，设置最小词数、平均词长、有效词比例、停用词比例、标点限制等条件（停用词采用spaCy德语列表）。
  4. **URL过滤**：使用UT1黑名单排除成人、广告、恶意软件等不良来源。
  5. **脏话过滤（Profanity Filter）**：基于LDNOOBW德/英词表，按比率阈值0.005过滤，而非文档级全删。
  6. **去重（Deduplication）**：先布隆过滤器，再MinHash（128排列，9桶×13行，相似度阈值0.8），逐dump进行。
- **教育质量分类与筛选（Quality Bucketing）**：
  - 使用Mistral-Small-24B-Instruct-2501作为LLM裁判，对1.4M文档进行0-5分教育质量评分。
  - 基于雪崩arctic-embed-m文本嵌入训练线性回归分类器，得到FineWebEdu German（FWe-de）评分器，对整个语料评分。
  - 消融实验表明：FWe-de(2)（评分≥2）效果优于低分数据，但FWe-de(3)（评分≥3）无进一步提升，故保留FWe-de≥2的文档。
- **合成数据改写（Synthetic Data Rephrasal）**：
  - 对FWe-de区间[1.5, 2)的83.93B token（Qwen3-8B tokenizer计）用Qwen3-8B按三种风格（专家教材、儿童教材、博客）进行改写，生成73.33B tokens。
  - 改写数据与原生FWe-de(2)/FWe-de(3)数据性能相当，证明改写可“提升”低质数据。
- **数据匿名化**：采用正则+Presidio库，将邮箱、电话、IBAN、信用卡号替换为类型占位符（<E-MAIL>等），应用于全部训练数据。

### 2.2 预训练（Pre-training）
- **架构**：基于前期研究（Schlotthauer et al., 2025），采用μP缩放、AdamW优化器、余弦/多项式学习率调度。最终配置：
  - 32层、32注意力头（GQA分组查询注意力）、头维度80、嵌入维度2560、LayerNorm、无bias、2层MLP、GELU激活，约2.7B参数。
  - 训练使用FSDP混合分片，最多32节点×4 NVIDIA H100。
- **Tokenizer设计**：系统探索66种配置，比较：
  - 数字处理：3位（右侧三位一组）优于1位。
  - 词表大小：65K > 52K > 16K（65K为节省内存上限）。
  - 数据配比：50%英语、40%德语、10%代码表现最佳；单语/纯代码配置较差。
  - 预分词器类似GPT-2/GPT-3，字母表限制512符号，NFKC归一化并去除重音。
- **学习率退火策略**：
  - 对比余弦（cosine）与多项式（polynomial）调度，每种含“无退火”和“显式退火”（180B稳定+20B线性退火）变体。
  - 多项式调度参数a、b通过480次小代理模型网格搜索优化。
  - 实验结论：带退火的模型优于不带退火的；多项式+退火在德语任务上表现最佳。

### 2.3 后训练与部署（Post-training & Deployment）
- **指令微调**：使用Sigma（自指令合成SFT数据集）、SystemChat2.0（系统消息）、GSM8K和WinoGrande增强数学与常识推理。
- **端侧部署**：开发Android demo应用，基于ExecuTorch框架，支持CPU推理；其他平台使用llama.cpp、MLX等。

## 6. 主要结论与发现

1. **数据质量重要性**：教育质量过滤（FWe-de≥2）可显著提升训练效率；低于阈值的数据虽非有害但教学价值低。
2. **改写有效性**：将FWe-de[1.5,2)数据改写后，其训练效果与原生的FWe-de(2)/FWe-de(3)数据相当，说明合成改写可“升级”数据质量。
3. **Tokenizer配置关键**：3位数字处理、65K词表、50%英/40%德/10%代码配比为最佳，直接影响推理效率与性能。
4. **退火策略**：显式退火阶段显著优于无退火；多项式调度+退火在德语任务上表现最佳。
5. **ELMOD-2.7B性能**：在<3B德语模型中表现最强，在德语ARC/HellaSwag/MMLU上匹配或超越部分7B模型，且训练token数远少于同类多语模型（如Llama-3.2-3B的9T vs ELMOD的4T）。
6. **端侧部署可行**：在Android手机CPU上即可达到4.4–21 tokens/s的速度，在边缘GPU上速度更高，验证了资源受限设备上运行2.7B模型的可行性。
