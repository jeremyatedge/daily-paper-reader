## 摘要
混合专家（MoE）模型对于边缘部署具有吸引力，因为它们提供了高模型容量，同时每个token仅激活少量参数，从而提高了计算效率。然而，边缘上的MoE推理从根本上受限于内存。专家参数规模庞大，由于容量、成本和功耗限制，通常驻留在片外内存中，使得专家加载成为关键路径。我们提出了APEX：自适应专家预取（Adaptive Expert Prefetching），这是一种预测性资源管理框架，可将专家加载与有用计算重叠进行。APEX引入了一个轻量级预取路由器，该路由器在注意力模块之前预测候选专家，并利用学习到的置信度模型动态获取额外专家。这种自适应策略实现了超过99%的重叠准确率，显著优于固定的top-k预取技术。APEX支持两种执行模式：保持正确性模式，保证精确的路由语义；以及无停顿模式，通过操作可用专家来消除残余停顿，且对应用准确性的影响可忽略不计。在多个MoE模型上，与最先进的基线相比，保持正确性模式将每个token的延迟最多降低26%，并将能量-延迟乘积（EDP）最多提高41%，而无停顿模式提供了额外的效率提升，且对应用准确性的影响可忽略不计。这些结果证明了自适应、置信度驱动的专家预取是边缘系统上高效MoE推理的有效方法。

## Abstract
Mixture-of-Experts (MoE) models are attractive for edge deployment because they provide high model capacity while activating only a small subset of parameters per token, improving compute efficiency. However, MoE inference at the edge is fundamentally limited by memory. Expert parameters are large and often reside in off-chip memory due to capacity, cost, and power constraints, putting expert loading to the critical path. We present APEX: Adaptive Expert Prefetching, a predictive resource management framework that overlaps expert loading with useful computation. APEX introduces a lightweight prefetch router that predicts candidate experts before the attention block to dynamically fetch additional experts using a learned confidence model. This adaptive strategy achieves over 99% overlap accuracy, significantly outperforming fixed top-k prefetching techniques. APEX supports two execution modes: a correctness-preserving mode that guarantees exact routing semantics, and a stall-free mode that eliminates residual stalls by operating on available experts with negligible impact on application accuracy. Across multiple MoE models, the correctness-preserving mode reduces per-token latency by up to 26% and improves energy-delay product (EDP) by up to 41% over state-of-the-art baselines, while the stall-free mode provides additional efficiency gains with negligible impact on application accuracy. These results establish adaptive, confidence-driven expert prefetching as an effective approach for efficient MoE inference on edge systems.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：大型语言模型（LLM）正越来越多地部署在边缘设备上，以满足低延迟、能效、隐私和降低云依赖等需求。混合专家（Mixture-of-Experts, MoE）模型因将模型容量与单token计算量解耦，被认为是边缘部署的理想选择——每个token仅激活少量专家参数，在严格的FLOPs预算下实现高精度。
- **核心瓶颈**：尽管MoE减少了计算量，但边缘MoE推理面临**根本性的内存瓶颈**。由于片上/封装内高速内存（如HBM）的容量、成本、功耗限制，全部专家参数必须存储在片外低速内存（如LPDDR）中，通过PCIe等较慢通道流式传输到加速器。论文测试表明：在代表性边缘平台上，**专家加载贡献了43%的延迟和29%的总能量**（对Granite-3.1-3B-A800M，1024 token上下文），且这种开销不仅仅是带宽问题，计算单元在等待期间仍持续消耗静态功耗。
- **现有方案的不足**：已有预测式预取方法（如ProMoE、HOBBIT、Fate等）大多采用**固定的top-k预取策略**，存在三个关键缺陷：
  1. **高平均重叠率并不等于无停顿执行**：即使平均重叠准确率很高（如75%-87.5%），只要每层存在一个专家预测错误，就会触发修正停顿。
  2. **Token级异质性**：不同token和层的路由不确定性差异显著，固定预算无法自适应调整。
  3. **运行时决策必须轻量化**：预取预算的确定需在注意力计算前完成，且开销需极小。

## 2. 提出的方法论

### 2.1 核心思想
APEX的核心理念是：**将专家加载从关键路径上的串行阻塞转变为预测性、置信度驱动的运行时决策**。通过在注意力块之前增加轻量级预取路由器，将传统的"路由 → 加载 → 执行"流水线转变为"预测 → 预取 → 执行"，利用注意力计算时间隐藏专家加载延迟。

### 2.2 关键技术细节

**（a）轻量级预取路由器**
- 放置在每层注意力块之前，是一个线性层加softmax，结构上镜像原始MoE路由器。
- 通过KL散度蒸馏损失训练，使其匹配原始路由器的专家选择分布，无需修改或重新训练基础MoE模型。
- 训练仅需前向传播冻结的基座模型，梯度只更新预取路由器。

**（b）自适应top-(k + δ̂(x))预取策略**
- 定义预取集合：K_p^{(δ)} = {e₁, e₂, ..., e_{k+δ}}，即预取排名前k+δ的专家。
- 定义Oracle额外预取预算 δ*：实现完全覆盖所需的最小δ，即最小δ使得原始路由器选择的集合 K_r ⊆ K_p^{(δ)}。
- **学习目标**：对每个token x，选择满足覆盖概率约束的最小δ：
  Pr(K_r \ K_p^{(δ̂(x))} = Ø | x) ≥ τ，其中τ为覆盖目标阈值。

**（c）序数Logistic CDF置信度模型**
- 将额外预取预算δ的最优值建模为序数分类问题，用CDF函数 p_δ(x) = σ(θ_δ - wᵀx) 估计"δ ≥ δ*"的概率。
- 其中θ_δ为有序阈值（θ₀ ≤ θ₁ ≤ ... ≤ θ_{N-k}），保证概率的单调性，构成有效CDF。
- 训练使用累积二元交叉熵损失 L_CDF = Σ H(p_δ(x), I[δ ≥ δ*])。
- 运行时：δ̂(x) = min{δ | p_δ(x) ≥ τ}，即选择满足覆盖阈值的最小预算。

**（d）两种执行模式**
1. **正确性保持模式**：严格遵循原始路由决策。若存在缺失专家，则异步发起修正取回，同时计算已加载的可用专家，最终仍使用完整的原始专家集。保证精确的MoE路由语义。
2. **无停顿模式**：若所有路由专家已预取则正常执行；否则保留已预取的被路由专家，用预取集合中原始路由权重最高的候补专家替换缺失专家（Algorithm 1）。通过近似消除修正停顿，以微小精度代价换取性能。

## 6. 主要结论与发现

- **APEX在4个模型上都实现了>97%（τ=0.90时）的每层重叠精度，高阈值（τ=0.97）下可达>99%**，接近Oracle水平，而ProMoE在多个层上仅达82-88%。
- **自适应预算有效追踪Oracle δ***，为简单层分配较小预算、困难层分配较大预算，实现了效率与覆盖率的平衡。
- **正确性保持模式**：延迟最多降低26%（vs ProMoE），EDP改善最高41%（vs ProMoE），能耗降低5.8-9.5%。
- **无停顿模式**：在Granite/DeepSeek模型上精度损失可忽略（如Granite-1B平均仅降0.5分），但**Phi-7B上精度下降显著**（如τ=0.60时从64.6降至58.6），归因于其k=2的稀疏路由结构。
- **过度预取不是免费的**：静态(k+8)预取能耗最高（377 mJ vs APEX 299 mJ），因为多余传输增加了I/O能量（97 mJ vs 56 mJ）。
- **开销极低**：附加参数占比仅0.022%-0.060%，性能开销仅0.009%-0.051%。
- **在不同带宽（32-1024 GB/s）和精度（4-32 bit）下均保持稳健收益**。

## 7. 优点

- **优雅的问题形式化**：将预取预算选择建模为序数分类/CDF问题，保障单调性且具有清晰的概率解释。
- **自适应性强**：按token和层动态调整预取预算，有效解决了路由不确定性的异质性问题。
- **模块化设计**：与基础MoE模型完全解耦，无需重训练基座模型，训练开销小，可跨数据集复用。
- **双模式支持**：在严格正确性（正确性保持模式）和极致性能（无停顿模式）之间提供了可配置的权衡。
- **严格的因果隔离**：静态过度预取基线使用相同的预取路由器排名，隔离了自适应预算的独立贡献。
- **评估方法严谨**：结合RTL综合、DRAM模拟和周期精确协同仿真，考虑了排队延迟、IOMMU开销等实际系统效应；能量分解直观说明APEX以少量I/O换取大量闲置能耗的机制。
- **低开销可部署性**：附加参数和计算量均极低，对实际系统部署友好。

## 8. 不足与局限

- **缺少真实硬件原型验证**：论文明确承认使用"综合校准的协同仿真"而非专用加速器原型的实测数据，系统级效应（如完整OS堆栈）未端到端建模。
- **低带宽场景收益受限**：在32-64 GB/s的低带宽下，注意力窗口只能隐藏部分专家传输，残余暴露时间仍制约性能提升。
- **Phi-7B上的精度退化**：无停顿模式在低top-k模型上精度损失显著（k=2时单专家贡献大）；该模式并非普遍适用，部署需谨慎评估。
- **训练依赖WikiText单一数据集**：虽然论文论证了预取路由器绑定的是模型路由函数而非特定任务，但未验证在极不同领域数据上训练辅助模型的表现。
- **CDF模型依赖于预取路由器的质量**：如果预取路由器排名严重劣化，CDF模型的校准也会受损。
- **未考虑训练成本/碳排放**：虽然辅助训练开销小，但论文未讨论其背后GPU能耗。
- **表格V中的表述特指Granite-3B**，能量分解结论对其他模型的可泛化性尚未展示。
