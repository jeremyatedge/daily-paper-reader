## 摘要
投机解码通过使用轻量级草稿模型推测多个令牌，减少昂贵的目标模型解码步骤，从而加速自回归大语言模型（LLM）的推理。其有效性在很大程度上取决于草稿选择，这促使了利用输入和生成阶段变化的自适应方法。然而，在内存受限的边缘设备上，由于在草稿模型之间切换的开销，这些方法往往无法提高端到端吞吐量。我们识别出该设置中的一个关键局限：在严格的内存预算下，草稿选择与草稿可用性之间的不匹配。为了应对这一挑战，我们提出了MemSpec，一种用于边缘设备上自适应投机解码的预测引导、内存感知运行时。MemSpec通过主动的驻留工作集管理将草稿选择与执行解耦。一个轻量级预测器从提示和生成上下文估计草稿有效性，而内存感知调度器减少反应式模型加载开销。在Jetson Orin Nano上的实验表明，MemSpec在稳态生成吞吐量上平均比最先进的基于bandit的自适应方法提高了40.7%，同时接近oracle上界。

## Abstract
Speculative decoding accelerates autoregressive large language model (LLM) inference by using a lightweight draft model to speculate multiple tokens, reducing expensive target model decoding steps. Its effectiveness depends heavily on draft selection, motivating adaptive methods that exploit variation across inputs and generation stages. On memory-constrained edge devices, however, these methods often fail to improve end-to-end throughput due to the overhead of switching between draft models. We identify a key limitation in this setting: the mismatch between draft selection and draft availability under tight memory budgets. To address this challenge, we present MemSpec, a prediction-guided, memory-aware runtime for adaptive speculative decoding on edge devices. MemSpec decouples draft selection from execution through proactive resident working-set management. A lightweight predictor estimates draft effectiveness from prompt and generation context, while a memory-aware scheduler reduces reactive model loading overhead. Experiments on a Jetson Orin Nano show that MemSpec improves steady-state generation throughput by 40.7% on average over state-of-the-art bandit-based adaptive methods while closely approaching the oracle upper bound.

### 1. 核心问题与研究动机

- **背景**：随着大语言模型（LLM）从云端向边缘设备（移动设备、嵌入式系统、边缘服务器等）迁移，内存受限条件下的高吞吐推理成为严峻的系统挑战。投机解码（Speculative Decoding, SD）通过轻量级草稿模型推测多个候选 token，再由更大的目标模型一次性验证，是加速自回归推理的经典方案。
- **核心问题**：投机解码的有效性高度依赖草稿模型的选择。不同草稿（如代码、数学、法律、医疗等领域的专用草稿）在不同提示词和生成阶段表现出显著差异的 token 接受率。这促使研究者提出自适应草稿选择方法（如多臂老虎机 MAB 方法），在运行时动态选择或切换候选草稿。
- **关键矛盾**：在内存受限的边缘设备上，**自适应切换带来的模型加载开销往往超过选型优化带来的收益**。论文指出，上一代自适应方法存在一个根本缺陷——**草稿选择与草稿可用性之间的不匹配（mismatch between draft selection and draft availability）**：选中的草稿未被加载驻留时，必须从慢速存储（如 NVMe）加载，切换延迟可高达单个 SD 迭代时延的 2.7 倍，频繁切换会直接抵消吞吐收益。
- **核心动机**：因此，边缘设备上的自适应投机解码不仅是**选择问题**，更是**内存约束下的调度问题**——需要确保"被选中的草稿在需要时确实可用"。

### 2. 方法论：MemSpec 设计

#### 核心思想

MemSpec 将草稿选择与执行解耦：**预测决定应该准备哪些草稿，执行则始终使用当前已驻留的最佳草稿**。通过主动的驻留工作集管理，避免阻塞式加载和过度模型切换。

#### 三个关键组件

1. **预测引擎（Prediction Engine）**
   - 使用**离线训练好的 BERT 编码器**作为草稿排序预测器，输入为 `[提示词 + 最近生成的 T 个 token]`，输出对各候选草稿的匹配概率：`p_i = f_θ(x_i)`。
   - 预测器无需高精度效用估计，只需能识别出少量有前景的候选草稿即可（即相对排序），因此十分轻量。推理时每 N 次 SD 迭代调用一次，开销平均仅占 3.9% 总执行时间。
   - 训练数据来源于投机解码执行轨迹，以"实际解码效用最高的草稿"为标签，与评估数据集隔离以防泄漏。

2. **草稿模型缓存管理器（Draft Model Cache Manager）**
   - 在容量为 K 的驻留缓存中，维护一个小型工作集 Wᵢ（由预测排序的前 K 名草稿构成），并增量更新驻留集 Gᵢ。
   - 对 Wᵢ 中尚未驻留的草稿执行**异步预取**；需要腾出空间时，按预测效用从低到高逐出候选草稿，同时尽最大可能保护当前活跃草稿不被逐出。
   - 通过这种增量重塑驻留集的方式，将草稿切换从"阻塞式即时切换"转化为"分段、重叠的过程"。

3. **运行时控制器（Runtime Controller）**
   - 核心策略：**非阻塞执行**——始终从当前驻留集合中选择最高分草稿作为活跃草稿执行，绝不等待非驻留草稿加载完成。
   - 定期执行"执行 SD 迭代 → 构造下一上下文 → 预测排序 → 更新缓存 → 选择下一活跃草稿"的循环（以 N 为调度间隔）。

#### 形式化描述

- 初始草稿选择：`d₀ = argmax P(d | x_prompt)`
- 调度点 i 的上下文：`xᵢ = [x_prompt ; x_recent(T)]`
- 预测分数向量：`pᵢ = {P(d | xᵢ) | d ∈ D}`
- 目标驻留集：`Wᵢ = TopK(Rᵢ)`（Rᵢ 为排序后的候选列表）
- 活跃草稿：`dᵢ* = argmax_{d ∈ Gᵢ} P(d | xᵢ)`（仅从驻留集选）
- 始终保持"活跃草稿 ∈ 驻留集 ⊆ 候选草稿全集"的约束。

### 6. 主要结论与发现

1. **静态选择不够**：Oracle-Static 较 General-Static 在归一化接受率上平均提升 40.3%，说明选择合适的专用草稿至关重要。
2. **动态适配有额外空间**：Oracle-Dynamic 较 Oracle-Static 进一步提升 25.7%，证明最佳草稿在同一生成过程中可能发生变化。
3. **探索式自适应方法在边缘设备上失效**：MAB-Async 虽然提升了接受率，但 46.4%~49.4% 的执行时间都花在"回退执行"（即使用次优草稿等待首选草稿加载完成）上，选择质量无法转化为吞吐。
4. **MemSpec 显著优于现有方法**：
   - 稳态吞吐量较 General-Static 提升 **58.8%**；
   - 较最先进的 MAB-Async 平均提升 **40.7%**；
   - 达到 Oracle-Dynamic 上界的 **95%~97%**；
   - 端到端延迟较 General-Static 降低 32.3%，较 MAB-Async 降低 24.9%。
5. **预测与内存管理必须协同**：Prediction-Only（无预取）仅提升 21.6%，与完整 MemSpec 差距 30.5%，说明预测准确率不是瓶颈，**确保预测草稿在需要时可用**才是关键。
6. **预测质量足够支撑实际应用**：Prompt + Recent 组合输入的预测器 Top-1 准确率 71.6%、**Top-2 召回率 95.7%**，意味着最优草稿几乎总能出现在驻留工作集中。

### 7. 优点

- **问题定位精准**：首次系统指出边缘场景下"草稿选择"与"草稿可用性"的系统性不匹配，将自适应投机解码重新定义为内存约束下的调度问题，识别了先前方法忽视的核心瓶颈。
- **设计优雅、解耦清晰**：将长时程规划（预测+缓存管理）与即时执行（选当前驻留最优草稿）分离，实现非阻塞自适应解码；算法描述（Alg. 1–3）清晰严谨。
- **预测成本极低**：用冻结 BERT + rank head 和定期间隔调用，将预测开销压缩到 3.9% 总执行时间，实际部署价值高。
- **实验验证充分**：多数据集、双模型族、四类基线、组件消融、参数敏感性、预测器质量、端到端延迟等多维度验证，形成完整证据链；对 MAB-Async 采用异步化强配置并调优参数，对比公平。
- **结论可推广**：性能增益在两种目标模型上呈现一致趋势，说明结论并非针对单模型族的偶然现象。

- **场景覆盖有限**：
  - 仅测试单 batch（batch size 1）、固定输出长度 128 token 的贪心解码；未评估 beam search、较长文本生成、多用户并发服务等场景。

- **未考虑异步预取与解码的显存/带宽竞争**：异步预取与解码并发执行时可能产生带宽争用，论文未分析由此带来的潜在干扰。
