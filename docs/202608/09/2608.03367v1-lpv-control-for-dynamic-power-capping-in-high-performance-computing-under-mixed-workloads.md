## 摘要
在节能与性能之间取得平衡仍然是高性能计算（HPC）系统中的一个关键挑战。虽然诸如Intel的Running Average Power Limit（RAPL）之类的静态功率上限机制提供了基本的控制能力，但它们缺乏适应动态变化工作负载的灵活性。这项工作研究了混合工作负载场景下的动态功率调节。我们研究了两种反馈策略：一种增益调度比例积分（PI）控制器和一种通过H∞控制合成的多胞线性参数变化（LPV）控制器，两者都由在内存和计算阶段之间变化的工作负载指标调度。我们评估了实际功率上限约束下的跟踪性能、相位切换和鲁棒性。虽然两种控制器都尊重功率限制，但LPV设计在相位变化期间实现了更低的跟踪误差、更低的控制方差和更平滑的瞬态。

## Abstract
Balancing energy consumption and performance remains a critical challenge in High Performance Computing (HPC) systems. While static power capping mechanisms such as Intel's Running Average Power Limit (RAPL) offer basic control capabilities, they lack the flexibility to adapt to dynamically varying workloads. This work studies dynamic power regulation for mixed workload scenarios. We investigate two feedback strategies: a gain scheduled proportional-integral (PI) controller and a polytopic linear parameter-varying (LPV) controller synthesized via H$\infty$ control, both scheduled by a workload indicator that changes between memory and compute phase. We evaluate tracking performance, phase switching, and robustness under practical power cap constraints. While both controllers respect power limits, the LPV design achieves lower tracking error, lower control variance, and smoother transients during phase changes than gain scheduled PI.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：高性能计算（HPC）系统在追求极致算力的同时面临巨大的能耗压力，而现有静态功率封顶机制（如 Intel RAPL）只能设置固定功率上限，无法动态响应应用在**内存密集**与**计算密集**阶段之间的切换，导致性能欠利用或能源浪费。
- **背景数据**：TOP500 中 196 台超级计算机年耗电量超过 30 亿千瓦时，相当于 80 万户家庭年用电量；El-Capitan 峰值性能达 1.742×10¹⁸ FLOPS，能耗问题已成为 HPC 的核心挑战。
- **现有局限**：DVFS/DPM 无法在硬件层面强制功率限制且依赖操作系统/作业调度器深度集成；RAPL 虽是硬件级机制，但内部逻辑不透明，静态或规则式使用无法适应应用运行时的功率特征变化。
- **整体含义**：需要一个能根据实时工作负载特征自动调节功率上限的闭环反馈控制框架，同时保证性能不低于用户容忍度，并满足硬件功率约束。

## 2. 方法论

### 2.1 核心思想
- 引入无量纲调度参数 **β ∈ [0,1]** 表示工作负载特征：β=0 为纯内存密集，β=1 为纯计算密集，中间值代表混合状态。
- 利用**反馈控制架构**（基于论文 [29] 的框架）：应用通过"心跳"信号向 Node Resource Manager（NRM）报告进度，控制器根据进度误差计算新的功率上限，经 RAPL 施加到处理器。

### 2.2 系统建模
- **内存密集模型**（STREAM benchmark 识别）：
  - 非线性稳态关系：Progress = K_L(1 − e^(−α(a·P_cap + b − β)))（K_L=42.4 Hz，α=0.032 W⁻¹）
  - 线性化一阶传递函数：**G_m(s) = (0.6269s + 0.01798) / (s + 0.05317)**
- **计算密集模型**（EP benchmark 识别）：
  - 一阶传递函数：**G_c(s) = (0.2361s + 0.4722) / (s + 1.783)**

### 2.3 增益调度 PI 控制器
- 经典 PI 控制律：u(t) = K_P·e(t) + K_I·∫e(τ)dτ
- 两个顶点控制器分别调参：内存（K_P=0.0213，K_I=0.0397）、计算（K_P=4.3161，K_I=8.1339）
- 按 β 线性插值增益：K_P(β)=(1−β)·K_P,mem + β·K_P,comp，K_I(β) 同理

### 2.4 多胞 LPV H∞ 控制器
- 将两个顶点的传递函数转为状态空间表示，构成多胞 LPV 模型：A(β)=Σαᵢ(β)Aᵢ（α₁=1−β，α₂=β）
- 引入两个加权函数：W_e 惩罚跟踪误差、W_u 限制控制活动；调节输出 z = [W_e·e, W_u·u]ᵀ
- 通过凸优化 LMI（线性矩阵不等式）在每个顶点求解 H∞ 合成问题，保证闭环系统满足 ∥T_zw∥∞ < γ∞
- 全局控制器由顶点控制器插值得到：K(β) = Σαᵢ(β)Kᵢ

### 2.5 核心区别
- **增益调度 PI**：工程直观但无正式稳定性保证，β 快速变化时增益突变可能引发振荡
- **LPV H∞**：通过 LMI 凸合成确保全工作范围内稳定性和鲁棒性，瞬态更平滑

## 6. 主要结论与发现

1. **两种控制器均能尊重功率上限**，有效跟踪参考进度信号。
2. **增益调度 PI 的局限**：β 快速变化时增益突变导致明显跟踪误差尖峰和短暂振荡；在激进场景下 Fit 从 89.9% 降至 78.7%，RMSE 从 2.69 增至 5.32。
3. **LPV H∞ 的性能优势**：
   - 平滑场景：Fit 92.9% vs 89.9%，RMSE 1.63 vs 2.69
   - 激进场景：Fit 92.7% vs 78.7%，RMSE 1.76 vs 5.32——性能几乎不随工作负载变化速度而劣化
4. **LPV 控制方差更低、瞬态更平滑**，频域上灵敏度函数满足设计模板，验证了鲁棒性。
5. 作者认为多胞 LPV 控制是 HPC 高动态工作负载下功率调节的可靠选择。

## 7. 优点

- **问题定位精准**：填补了现有功率封顶控制仅针对单一工作负载类型的空白，直击混合工作负载这一实际稀缺场景。
- **方法结合了理论与实用**：系统建模基于真实 benchmark 数据，控制器合成采用形式化的 LMI/H∞ 框架，稳定性保证比经验调参的 PI 更强。
- **β 参数设计简洁有效**：以单个无量纲参数插值两个极端工况，既保持了模型的简洁性，又覆盖了中间混合状态。

## 8. 不足与局限

- **β 假设理想化**：论文假设 β 在每个控制周期无延迟可用，但实际需从硬件性能计数器（缓存未命中率、指令/分支活动、I/O 传感器）实时估计，估算器的设计与验证超越了本文范围。
- **仿真验证的局限**：全部评估基于简化 SISO 线性模型，未捕捉真实 RAPL 执行的非线性动力学、平台差异和潜在延迟，结论在真实硬件上可能有所偏离。
- **模型覆盖范围窄**：只覆盖内存密集（STREAM）和计算密集（EP）两个极端，I/O 密集、GPU 异构负载、多节点交互等未纳入建模。
