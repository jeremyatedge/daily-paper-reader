## 摘要
我们引入Opt.Gear，一个专为高效端侧部署、实时推理和强大任务能力而设计的基础模型。它包含稠密模型（1M、270M和1B），上下文长度为64K。我们设计了一种新的混合架构，将卷积键值门控混合器与局部-全局注意力相结合，以减少随着长上下文而指数级增长的KV缓存内存。与类似规模的模型相比，该架构在NPU上的预填充和解码速度最高可提升4.9倍。从2T令牌的候选语料库中，Opt.Gear在一个精选的0.5T令牌子集上进行训练，无需知识蒸馏。这是现有基础模型中数据效率最高的。所有模型均以开放权重和针对ONNX、高通NPU和苹果ANE的部署二进制文件形式发布，使Opt.Gear成为需要快速、内存高效推理和强大任务能力的边缘应用的实用基础。此外，为了扩展端侧生成语言模型的生态系统，我们推出了Opt.Gear-1M，该模型可部署在微控制器单元（MCU）上，是一种微型语言模型（TLM）。Opt.Gear-1M是首个在STM32H747I-DISCO开发板的ARM Cortex-M7 CPU上通过W4A32量化实现20 TPS的生成语言模型。

## Abstract
We introduce Opt.Gear, a foundation model designed for efficient on-device deployment, real-tim inference, and strong task capability. It includes a dense model (1M, 270M, and 1B) with a context length of 64K. We designed a new hybrid architecture that combines a convolutional key-value gated mixer with local-global attention to reduce the KV-cache memory that tends to increase exponentially with long context. This architecture delivers up to X4.9 faster prefill and decoding speeds on the NPUs compared to models of a similar scale models. From a 2T tokens candidate corpus, Opt.Gear is trained on a curated 0.5T tokens subset without knowledge distillation. This is the most data-efficient of the existing foundation models. All models are released with open weights and deployment binaries for ONNX, Qualcomm NPU, and Apple ANE making Opt.Gear a practical base for edge applications that need fast, memory-efficient inference and strong task capabilities. Furthermore, to expand the ecosystem of on-device generative language models, we are introducing the Opt.Gear-1M that can be deployed on Micro-Controller Units (MCUs), a Tiny Language Model (TLM). Opt.Gear-1M is the first generative language model to achieve 20 TPS with W4A32 quantization on the ARM Cortex-M7 CPU of the STM32H747I-DISCO.

- **核心问题**：端侧（手机、平板、机器人、嵌入式设备等）部署大语言模型时，面临严格的内存、功耗、实时性约束。传统全注意力架构的 KV-Cache 随上下文长度增长而线性膨胀，且注意力计算复杂度为 O(N²)，在 NPU/GPU 等边缘硬件上成为显著瓶颈。
- **动机**：现有开源模型（如 Llama、Gemma 等）多针对服务器级 GPU 优化，无法直接高效运行在资源受限的移动与边缘设备上。论文旨在设计一种**硬件感知的混合架构**，在不明显损失下游任务质量的前提下，大幅提升端侧推理速度、降低内存占用，并保持长上下文能力。
- **整体含义**：Opt.Gear 是一组面向设备端部署的基础模型族（1M、270M、1B），强调数据效率、部署兼容性和跨硬件（MCU、移动 NPU、GPU）的实用性。其开源权重与 ONNX / Qualcomm NPU / Apple ANE 二进制进一步推动端侧生成模型生态发展。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **总体架构**：混合架构 = 少量全局注意力层（GQA）+ 局部注意力层 + ConvKV-Gated Mixer 层。
  - 全局注意力：负责长距离上下文路由与全局信息聚合。
  - 局部注意力：保持固定窗口（如 512）内的中距离上下文。
  - ConvKV-Gated Mixer：替代大部分滑动窗口局部注意力层，处理短距离上下文，为端侧高效推理的核心组件。
- **ConvKV-Gated Mixer 具体机制**：
  1. 输入 token 分别投影为 query、key、value：`q_t = x_t W_q`，`k_t = x_t W_k`，`v_t = x_t W_v`。
  2. 对 key 和 value 施加**因果深度可分离 1D 卷积**：  
     `ek_t = Σ_{i=0}^{L_conv-1} a_i ⊙ k_{t-i}`，`ev_t = Σ_{i=0}^{L_conv-1} b_i ⊙ v_{t-i}`。
  3. 用卷积后的 key 调制 query，经 sigmoid 生成门控：  
     `g_t = σ(q_t ⊙ ek_t)`，`y_t = g_t ⊙ ev_t`。
  4. 输出投影：`o_t = y_t W_o`。
  - 该模块**无注意力矩阵、无 softmax、无序列长度的 KV 缓存**，仅保留固定大小的卷积状态。
- **内存高效缓存机制**：
  - GQA 全局缓存为 O(2·C·d_kv)，滑动窗口注意力为 O(2·W·d_kv)，而 ConvKV 缓存为 O(2·L_conv·d_kv)。
  - 由于 L_conv 远小于滑动窗口大小且与上下文长度无关，显著减少解码时的活动状态与内存带宽需求。
  - 在 Opt.Gear-270M / 1B 中 L_conv=3，Opt.Gear-1M 中 L_conv=4。
- **模型配置要点**（见表 1）：
  - Opt.Gear-1B：d_model=1152，26 层，FFN=6912，GQA（4 query heads / 1 KV head），head dim=256，上下文 65536。
  - Opt.Gear-270M：d_model=640，18 层，FFN=2048，GQA 同上，上下文 65536。
  - Opt.Gear-1M：d_model=128，5 层，FFN=272，GQA（2 query heads / 1 KV head），head dim=64，上下文 512，词表仅 2048（byte-level BPE）。
  - 位置编码采用 RoPE，全局 theta=1,000,000，局部 theta=10,000（1M 无局部）。
  - 非线性和前馈激活：1B/270M 用 GeGLU，1M 用 ReLU6GLU。
- **量化感知训练（QAT）**：
  - 采用 GPTQ 思想的层输出重建目标，用校准激活估计各层敏感性，初始化为 INT4 分组 scale：  
    `Δ* = argmin_Δ ||W X - Q_Δ(W)X||_F^2`。
  - 基于 Hessian 信息初始化后，再使用 LSQ（Learned Step Size Quantization）将每个量化组的 scale 作为可学习参数，通过直通估计器做反向传播，联合优化权重与 scale。
  - 训练过程始终模拟 W4A16 部署格式，避免量化器不匹配。
- **训练流程**：
  1. 预训练：从 2T 候选语料过滤、去重、均衡后得到 0.5T tokens（92% 英文，6% 韩文，2% 数学，无代码数据），不使用任何知识蒸馏。
  2. 长上下文扩展：使用 prolong-data-64k 语料，分两阶段从 4K 扩展到 32K 再到 64K（每阶段 10B tokens）。
  3. 后训练：通用 SFT + 推理导向 SFT；Opt.Gear-1M 则直接用 GPT 生成的 STM32 板控合成数据（50,000 条）训练为“指令→结构化 JSON 控制意图”的专用模型。

## 6. 论文的主要结论与发现

- **数据效率突出**：仅用 0.5T tokens 且无知识蒸馏，Opt.Gear-270M / 1B 在多数英韩基准上达到或超过使用 2T–36T tokens、甚至蒸馏的同类模型（如击败 Gemma3-270M、Gemma3-1B、EXAONE 4.0-1.2B 等）。
- **端侧 NPU 推理加速显著**：在 Qualcomm QAIRT 下，Opt.Gear-1B 在 Snapdragon GEN5 上预填充达 7,042 tokens/s，解码 86 tokens/s，明显快于 Llama3.2-1B（4,481 / 65）、Gemma3-1B（3,226 / 61）；架构文档称最高可比同规模模型快 ×4.9。
- **跨运行时/硬件具有强兼容性**：CoreML 下在 iPhone 17 Pro 上同样领先；llama.cpp 下 CPU/GPU 表现稳定，但 NPU 后端受限于滑动窗口注意力支持而退步，反衬出专用运行时优化的必要性。
- **量化稳定性好**：QAT 预训练后的 Opt.Gear-1B 在叠加 RTN/AWQ/GPTQ 时性能下降很小，优于 Gemma3-1B，且在韩语基准上保持稳定。
- **MCU 部署可行**：Opt.Gear-1M 在 Cortex-M7 上以 W4A32 量化达到 20 tokens/s（50 ms/token），是首个在 MCU 上实现交互式自回归生成的语言模型。
- **无蒸馏训练的可复现性与可解释性**：训练流程简单、资源需求明确，更直接地体现架构与数据的真实效率。

## 7. 优点

- **硬件感知架构创新**：用固定大小卷积状态替代局部注意力的序列长度相关 KV 缓存，显著降低解码期内存带宽压力，且算子（线性、卷积、逐元素乘、sigmoid）在 CPU/NPU/GPU 上普遍易映射，无需定制序列内核。
- **数据效率与透明性**：明确拒绝知识蒸馏，在极紧凑计算预算下完成训练，使模型能力与数据质量、架构效率的关系更清晰。
- **量化方案严谨**：结合 GPTQ 式 Hessian 初始化和 LSQ 可学习尺度，统一量化网格，从初始化到部署端到端一致，鲁棒性好。
- **评估范围广**：覆盖多硬件（MCU、手机 CPU/GPU/NPU）、多运行时（QAIRT、llama.cpp、CoreML）、多任务（英韩语言、推理、韩国文化）以及多种量化方法，实用性验证扎实。
- **开源与生态贡献**：发布开源权重 + ONNX / Qualcomm NPU / Apple ANE 部署二进制，并支持 Transformers、llama.cpp、ExecuTorch、vLLM，推动边缘 AI 落地。
- **针对极低资源场景的专门设计**：Opt.Gear-1M 的 2,048 词表、512 上下文、ReLU6GLU 等设计都服务于 MCU 的 flash/SRAM 限制，体现了从硬件约束倒推模型设计的完整思路。
