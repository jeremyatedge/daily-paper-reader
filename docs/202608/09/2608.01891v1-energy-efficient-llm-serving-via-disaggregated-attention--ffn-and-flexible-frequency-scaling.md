## 摘要
大语言模型（LLM）服务涵盖具有严格服务级别目标（SLO）的多样应用，通常需要GPU以最高频率运行，从而增加能耗。现有的能耗管理方法仅在请求或推理阶段级别调整GPU频率，忽略了注意力（Attention）与前馈网络（FFN）在算子级别对频率敏感性的差异。我们发现，注意力与FFN（A/F）的能耗最优频率不同，并随推理阶段、工作负载和系统配置而变化。然而，运行时可变性和独立的A/F频率控制带来了巨大的搜索空间和高通信开销。为应对这些挑战，我们提出了AFlex，一个针对分离式A/F服务联合优化资源供给与GPU频率缩放的框架。AFlex引入了全局调度器和本地算子级动态电压与频率缩放（DVFS）控制器，以确定A/F资源分配和频率。它进一步引入了具有动态微批次深度和自适应请求批处理的交错A/F流水线，以减少流水线气泡。我们在SGLang中实现了AFlex，并在NVIDIA A800 GPU上使用Qwen3-32B和Mixtral-8$\times$7B模型，在生产的Conversation和Coding迹线下进行评估。与最先进的分离式服务相比，AFlex将每token能耗降低高达49%，与频率缩放系统相比降低48%，同时满足TTFT和TPOT SLO要求。

## Abstract
Large language model (LLM) serving spans diverse applications with stringent service-level objectives (SLOs), often requiring GPUs to run at maximum frequencies and increasing energy consumption. Existing energy-management approaches adapt GPU frequencies only at the request or inference-phase level, overlooking operator-level differences in frequency sensitivity between Attention and feed-forward networks (FFNs). We find that the energy-optimal frequencies of Attention and FFN (A/F) differ and vary with the inference phase, workload, and system configurations. However, runtime variability and independent A/F frequency control create a large search space and high communication overhead. To address these challenges, we present AFlex, a framework that jointly optimizes resource provisioning and GPU frequency scaling for disaggregated A/F serving. AFlex introduces a global scheduler and a local operator-level dynamic voltage and frequency scaling (DVFS) controller to determine A/F resource allocations and frequencies. It further introduces an interleaved A/F pipeline with dynamic microbatch depth and adaptive request batching to reduce pipeline bubbles. We implement AFlex in SGLang and evaluate it on NVIDIA A800 GPUs using Qwen3-32B and Mixtral-8$\times$7B under production Conversation and Coding traces. \AFlex reduces energy per token by up to 49\% over state-of-the-art disaggregated serving and 48\% over frequency-scaling systems while satisfying TTFT and TPOT SLOs.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：LLM（大语言模型）服务已成为现代数据中心的主要 GPU 工作负载，其运行需满足严格的 SLO（服务级别目标），包括 TTFT（首 token 时延）和 TPOT（每输出 token 时延）。为满足 SLO，GPU 往往以最高频率运行，导致能耗显著增加。
- **现有方法不足**：已有的能耗管理方案（如 DynamoLLM、throttLL’eM、GreenLLM、BiScale 等）仅在请求级或推理阶段级（prefill/decode）调整 GPU 频率，**忽略了算子级（Attention vs FFN）在频率敏感性上的本质差异**。
- **关键观察**：
  - Attention 与 FFN（A/F）的最优运行频率不同，且随推理阶段、工作负载、batch size、TP 度等配置动态变化。
  - 单一 GPU 频率无法同时匹配二者的时延敏感性和最优能量点；同构 A/F 资源配置会导致流水线气泡和能量浪费。
  - 然而，A/F 分离式执行引入巨大搜索空间和隐藏状态传输/频率切换开销，直接应用不可行。
- **整体含义**：能否将 A/F 分离执行与算子级 DVFS 结合，并联合优化资源配置与频率选择，以在满足 SLO 的前提下显著降低能耗，是本文要解决的核心问题。该问题的解决为绿色 LLM 服务提供了一条可行的技术路径。

## 2. 论文提出的方法论

### 核心思想
AFlex 是首个将 **Attention–FFN 分离执行（AFD）** 与 **独立算子级 GPU 频率缩放（DVFS）** 相结合的 LLM 服务框架。它将 PA、PF、DA、DF（prefill Attention、prefill FFN、decode Attention、decode FFN）视为四个独立的执行与频率控制域，通过两级控制平面实现粗粒度的资源规划与细粒度的运行时频率调节。

### 架构组成
1. **Global Scheduler（全局调度器）**：
   - **Profiling and Predictor**：离线扫描 TP 度、GPU 频率、batch size、序列长度，采集 A/F 算子的时延与能耗数据；训练轻量级梯度提升树回归模型，用于在线预测。
   - **Workload Monitor**：每 300 秒追踪集群健康状态，在 SLO 违反、A/F 不均衡、P/D 阶段偏斜或负载分布漂移（KL 散度超阈值）时触发重配置。
   - **Resource Orchestrator**：以整数线性规划（ILP，见公式 1a–1f）为基础，在 GPU 总数、显存、TTFT/TPOT 预算、吞吐量约束下，选择最小化能耗的 A/F 资源配置（A/F 对数量、TP 度、基准频率）。
   - **Runtime Reconfiguration Engine**：采用**增量权重重分片**技术，在后台异步准备目标 TP 布局，复用驻留分片、仅传输缺失分片，避免中断在线服务。
2. **AFD Data Plane（分离式数据平面）**：
   - **Placement-aware Data Path**：支持跨节点/节点内隐藏状态传输，通过 NIC affinity 分组实现与 TP 度无关的跨节点通信。
   - **Interleaved A/F Pipeline**：交错调度 A/F 微批次，动态选择微批次深度 M 和请求 batch size，以减少流水线气泡，隐藏状态传输可被计算重叠（见公式 2）。
3. **Local DVFS Controller（本地 DVFS 控制器）**：
   - **Prefill DVFS**：在启动前一次性地选择最优 PA/PF 频率对，以最小化批能量并满足剩余 TTFT 预算。
   - **Decode DVFS**：采用窗口化算法（Algorithm 1），根据迭代时间、batch size 变化率、切换开销设置自适应频率更新窗口，在满足 TPOT 的前提下惰性切换到能量最优的频率对。

### 关键公式
- **ILP 优化目标**（公式 1）：最小化四池总能量，约束为 GPU 总数、显存上限、每层 TTFT/TPOT 预算、阶段吞吐量。
- **流水线时延模型**（公式 2）：\( t_{layer} = t_A + t_F + t_{comm} \) 当 \( M=1 \)；\( t_{layer} = \max(t_A, t_F) + t_{comm}/M \) 当 \( M≥2 \)。

### 算法流程示例
Algorithm 1（窗口化 Decode DVFS）：更新窗口计数器 → 检测 batch 变化和时延 → 若条件稳定则不切换；否则计算 TPOT 可行频率集合 \( F_\tau \)，选能量最小者 \( f^* \)，若当前频率已超 SLO 则立即切换，否则在考虑切换开销均摊后惰性切换。

## 6. 主要结论与发现

- AFlex 在 Conversation 和 Coding 生产轨迹下，每 token 能耗较最先进的**分离式服务（DistServe）降低最高 49%**，较**频率缩放系统（DynamoLLM）降低最高 48%**，同时满足 TTFT 和 TPOT SLO。
- 相比于最优基线，AFlex 在不同 RPS 下实现 19.6%–46.8% 的能耗降低。
- 细粒度 A/F 解耦控制可将总体平均 GPU 频率降至约 530 MHz（基线系统为最大频率或 966–1357 MHz），大幅降低能耗。
- 在轻负载（2 RPS）下 AFlex 仍保持高效，而基线系统能耗增长显著；异步阶段压力（decode-heavy 或 prefill-heavy）下，孤立的粗粒度控制无法充分优化，AFlex 仍能以 4%–55% 的幅度超越最优基线。
- 在扩展到 4 节点集群以及 MoE 模型上，AFlex 的优势保持一致（至少 20.2% 的能耗降低）。
- 消融表明：动态微批次深度和自适应请求批处理分别可减少 65.1% 和 16.1% 的流水线气泡；增量重分片可降低 52–72% 的重配置开销；ILP 求解开销小于调度窗口的 0.2%。

## 7. 优点

- **问题洞察深入**：首次系统性揭示 Attention 与 FFN 在频率敏感性上的算子级差异，并量化了同构资源配置的能耗损失。
- **两级控制平面设计巧妙**：将全局粗粒度资源规划（ILP）与本地细粒度 DVFS 解耦，兼顾 SLO 可行性与运行时的动态适配能力。
- **工程实现考虑周全**：增量权重重分片、后台异步重配置、NIC-affine 跨节点通信、窗口化频率切换以摊销切换开销，均体现了对系统开销的细致关注。
- **交错 A/F 流水线**：动态微批次深度和自适应请求批处理有效减少流水线气泡，在负载波动下保持高 GPU 利用率和低时延。
- **评估全面且结论翔实**：多模型、多工作负载、多集群规模和完整消融，实验证据充分，节能幅度显著，且全部在 SLO 约束内达成。

## 8. 不足与局限

- **平台单一**：实验仅在 NVIDIA A800 上进行，缺乏对 H100/H200 或其他厂商 GPU 的验证，DVFS 特性与最优频率因架构而异，泛化性有待证明。
- **模型覆盖有限**：仅测试了两个模型（Qwen3-32B 稠密、Mixtral-8×7B MoE），对小规模模型、超大模型或不同注意力实现（如线性注意力）未做检验。
- **离线 profiling 成本未量化**：预测器依赖离线采集覆盖 TP×频率×batch×序列长度的大规模扫描数据，该开销未被纳入讨论。
- **重配置时延仍然较高**：尽管增量分片有显著改善，重配置仍需 3.5–4.0 秒，在高动态负载场景下可能影响响应性。
- **跨节点通信瓶颈**：A/F 分离涉及逐层隐藏状态传输，通信开销在多节点和较大模型下可能进一步放大，论文对该场景的边界讨论偏少。
- **模型未开源**：论文承诺最终版本公开代码，当前无法独立复现实验结果，存在一定的不确定性。
