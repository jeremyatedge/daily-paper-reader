## 摘要
在边缘设备上部署大型语言模型（LLM）通常依赖于模型压缩或分裂推理。然而，压缩会降低推理能力，而分裂推理则饱受严重的广域网（WAN）通信瓶颈之苦。边云投机解码作为一种有前景的替代方案应运而生，利用边缘小模型生成令牌供云端验证。然而，在不稳定的广域网上，不可避免的预测拒绝会引发灾难性的流水线停顿和全网回滚，从而抵消协作收益。为克服这一问题，我们提出了AceSpec——一种非对称的边云协作框架。AceSpec利用未饱和的边缘计算资源主动构建概率状态缓存，有效地将全网范围内的流水线冲刷转化为O(1)局部内存查找。为节省带宽，它采用非对称通信协议，上行传输最小主链索引，下行传输紧凑的稀疏分布。此外，我们引入了一种网络感知的、基于拉格朗日优化的资源分配策略，动态最大化局部缓存命中率。评估表明，AceSpec实现了高达3.52倍的吞吐量加速，并表现出卓越的带宽免疫性，即使在严重受限的50 Kbps广域网条件下也能维持接近峰值的推理性能。

## Abstract
Deploying Large Language Models (LLMs) on edge devices typically relies on model compression or split inference. However, compression degrades reasoning capabilities, while split inference suffers from severe Wide Area Network (WAN) communication bottlenecks. Edge-cloud speculative decoding emerges as a promising alternative, leveraging an edge small model to draft tokens for cloud verification. Yet, over volatile WANs, inevitable prediction rejections trigger catastrophic pipeline stalls and network-wide rollbacks, neutralizing collaborative gains. To overcome this, we propose AceSpec, an asymmetric edge-cloud collaborative framework. AceSpec utilizes un-saturated edge compute to proactively construct a probabilistic state cache, effectively transforming network-wide pipeline flushes into $\mathcal{O}(1)$ local memory lookups. To preserve bandwidth, it employs an asymmetric communication protocol that transmits minimal main-chain indices uplink and compact sparse distributions downlink. Furthermore, we introduce a network-aware, Lagrangian-optimized resource allocation strategy that dynamically maximizes the local cache hit rate. Evaluations demonstrate that AceSpec achieves up to a 3.52$\times$ throughput speedup and exhibits exceptional bandwidth immunity, sustaining near-peak inference performance even under severely constrained 50 Kbps WAN conditions.

  - **投机解码（Speculative Decoding）**：理论上可将通信负载从稠密张量压缩为离散令牌序列，但其传统设计隐含假设近零通信成本。直接部署在边云WAN场景时，同步"停等"式的草稿-验证依赖导致严重通信瓶颈。
- **既有边云推测解码方案的不足**：
  - 现有异步流水线方案（如PicoSpec、PipeSD、E2-SCI）虽部分缓解了延迟，但存在系统性缺陷：
    - 单链状态同步架构下，预测拒绝会引发流水线停顿与全网络级回退惩罚；
    - 为节省上行带宽，往往牺牲对随机核采样（nucleus sampling）的支持，退化为确定性贪心解码，限制了真实生成任务的多样性需求；
    - 批量传输机制对早期令牌拒绝极为敏感，导致带宽浪费；
    - 需要额外微调或辅助网络，降低了通用性与即插即用的部署灵活性。
- **研究含义**：提出一种**无需训练、通信高效、支持随机采样**的边云协作LLM推理方案，在易变WAN环境中将推理性能从"网络受限"转向"算力受限"，使边缘设备获得接近本地的推理体验。

## 2. 方法论：核心思想、关键技术细节与公式

### 2.1 核心思想

- **总体原则**：利用边缘设备充裕的并行计算资源，换取昂贵的WAN回退成本下降。
- **核心思路**：在云端异步验证窗口内，用边缘SLM主动扩展一棵**概率多分支令牌树**并缓存在本地；当云端拒绝主链令牌时，边缘通过**O(1)局部内存查找**直接恢复正确分支状态，将"全网流水线冲刷"转化为零开销的本地操作。

### 2.2 关键技术细节

1. **非对称通信协议（Asymmetric Communication Protocol）**：
   - 上行：仅传输主链（main chain）的令牌索引构成的标量数组，不传整棵多分支树，也不传全词表概率分布。
   - 下行：云端拒绝时，仅返回拒绝位置索引（π）及该位置的**稀疏化目标概率分布**（ˆPtarget）。
2. **异步多分支树扩展**：
   - 云端处理期间（Tcloud = RTT + Tverify），边缘SLM从主链各潜在拒绝深度并行扩展备选分支。
   - 使用自定义**树注意力掩码**（Tree Attention Mask，含共享前缀块、主路径分支约束块、后缀对角隔离块），将N条分支打包成单次前向传播，使扩张时间接近O(1)。
3. **O(1)状态恢复**：
   - 收到云端反馈后，本地重采样（Resample）确定正确令牌，用校验结果w=(π, x_resampled)作为查询键查本地缓存；命中则用COMPACT_KV操作对齐KV缓存并废弃无关分支。
4. **两阶段受约束的资源分配**：
   - 网络感知预算控制 + 任务感知拓扑分配（见下）。

### 2.3 核心公式与算法流程

- **系统瓶颈量化**：流水线回退惩罚的期望值：
  - E[Penalty] = (1 − α^γ) × (RTT + T_redraft(γ))，其中α为单令牌平均接受率，γ为草稿长度。
- **系统加速比下界**：
  - S ≥ S_ideal / [1 + (1 − P_tree_hit(T))·ρ]，其中S_ideal为理想最大加速极限，ρ为回退惩罚比。
- **网络感知计算预算**：
  - B*(t) = min{B_max, ⌊T⁻¹_tree_draft(RTT(t) + T_verify)⌋}
- **任务感知分支分配**：以最大化整树命中率 P_tree_hit(F) = ∏ p(F_k) 为目标，经拉格朗日乘子法求解，得到**非均匀几何衰减闭式解**：
  - F*_k = B_alloc(t) · (1−η)/(1−η^γ) · η^k，其中η = α^(1/(β+1))，β为LLM词表分布的幂律衰减指数。
- **算法流程（Algorithm 1）**：初始化草稿 → 异步传输主链 → 边端异步扩展树 → 等待云端验证 → 本地重采样 → O(1)缓存查找 → KV压缩 →（未命中则回退KV并顺序重起草）。

## 6. 主要结论与发现

- AceSpec在多数配置下达到最优或接近最优的吞吐加速：
  - 最佳场景：LLaMA-1B/70B + HumanEval，加速比达**3.52×**；
  - Qwen-0.6B/32B + GSM8K达1.75×，优于PicoSpec（1.45×）和DSSD（0.85×）。
- **带宽免疫性**：带宽从100 Mbps降至50 Kbps时吞吐几乎不变，仅在≤25 Kbps时性能才开始下降，验证了非对称通信协议对网络波动的高度适应。
- **消融实验验证理论**：非均匀分支分配在各数据集上优于均匀分配与单链架构（如GSM8K：24.37 tokens/s vs. 21.58 vs. 20.14），且非均匀策略的TTFT也优于均匀策略（436.62 ms vs. 450.79 ms），说明将计算预算集中于浅层高概率分支更有效，同时也避免了均匀扩张导致的边缘初始调度延迟。
- **命中率维持**：高随机温度（T≥1.5）下，缓存命中率仍维持在81%以上，说明多分支缓存覆盖了足够的候选令牌空间，可支持创造性生成任务。
- **发现边界条件**：Qwen-1.7B/32B在HumanEval上加速比降至0.98×——草稿模型规模增大使本地树扩展耗时超过云端处理窗口，流水线转为边缘算力受限，与Network-Aware Budgeting的约束预测一致，说明多分支扩张必须被限制在WAN往返时间窗口以内。

## 7. 优点

- **训练自由、通用性高**：无需对边缘SLM或云端LLM做任何微调或增加辅助模块，可直接部署现有开源模型。
- **原生支持随机核采样**：不同于PipeSD与E2-SCI退化为贪心解码，AceSpec完整保留生成多样性与数学正确性。
- **通信开销极低**：上行仅传标量索引数组，下行传稀疏分布，从根本上规避了带宽墙；还利用边缘空闲算力替代昂贵的重计算。
- **扎实的理论框架**：将资源分配建模为双层优化问题，并基于LLM词表幂律分布特性导出拉格朗日闭式解（非均匀几何衰减），理论推导完整清晰；解析公式揭示了"分支应集中在浅层高脆弱点"的直觉。
- **O(1)状态恢复设计巧妙**：将云端的异步验证窗口转为本地树扩展时间，配合COMPACT_KV实现内存连续对齐，消除了顺序重起草惩罚，将复杂系统问题简化为缓存问题。
- **实验在受限边缘设备上验证了可行性**：在真实的嵌入式GPU（Jetson AGX Orin）上进行测试，而非仅在数据中心GPU模拟，增强了说服力。

## 8. 不足与局限

- **边缘设备算力受限时的性能退化**：论文承认一个反向失效案例——Qwen-1.7B/32B + HumanEval配置下，较大的草稿模型导致本地树扩展无法在云端往返时间内完成，系统由"网络受限"转为"边缘算力受限"，加速比降至0.98×。这意味着AceSpec的实际增益对边缘设备算力/模型的匹配异常敏感，在算力较弱的真实边缘节点上存在加速失效风险。
- **部署的基础设施前提较高**：非对称多分支缓存要求边缘SLM具备大VRAM与并行束级前向能力，这与"SLM本身只需轻量"相冲突；自定义树注意力掩码在CSR/注意力内核上的实现兼容性，对现有推理引擎是否友好未充分讨论。
- **评估多为模拟环境**：实验基于模拟WAN而非真实遥测网络，实际网络波动模式（突发抖动、丢包）的影响尚待检验；仅报告了带宽梯度实验，未对RTT变化、带宽抖动模式等系统变量做全面扫描。
- **算法参数依赖未充分讨论**：影响分配的β（幂律尾指数）与c等作为超参未报告其估计方法；在分布偏离幂律假设的应用上，几何分配可能非最优。
- **未来工作**：作者坦言多分支机制当前的算子与内存管理开销较大，需引入融合注意力内核等进一步优化。
- **缺少并行请求/批处理场景**：只评测了单条流的端到端性能；在更高VRAM占用条件下，树缓存扩展与线上数据流在边缘端的并发竞争关系尚不明确。
