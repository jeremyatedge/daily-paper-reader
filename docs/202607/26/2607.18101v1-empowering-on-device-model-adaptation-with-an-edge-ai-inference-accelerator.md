## 摘要
设备端模型适配对于在资源受限硬件上实现终身个性化至关重要，但此类设备的计算、功耗和内存限制使得端到端反向传播对现代深度神经网络来说不切实际。本文提出了一种异构适配流水线，该流水线重新利用商用边缘AI推理加速器Hailo-8L，在设备端训练期间进行冻结骨干特征提取。计算图被分割，使得预训练骨干被量化为INT8并在加速器上运行，而仅在主机CPU上微调一个轻量级FP32分类头，从而实现在大部分权重保持不变的情况下，频繁且能效高的现场更新。在多种架构和数据集上，该流水线与树莓派5 CPU基线相比，实现了高达15.4倍的挂钟训练时间加速，在有利设置下提供了有竞争力的吞吐量，并始终降低了每样本能耗。训练后量化恢复被证明对于保持加速器生成特征的质量和减轻量化敏感架构中的精度损失至关重要。总体而言，实验结果展示了一种利用面向推理的边缘加速器实现高效设备端适配的实用方法。实现代码见https://github.com/MatPiech/accelerator-training。

## Abstract
On-device model adaptation is essential to enable lifelong personalization on resource-constrained hardware, but compute, power, and memory limitations of such devices make end-to-end backpropagation impractical for modern deep neural networks. This work proposes a heterogeneous adaptation pipeline that repurposes a commercial edge AI inference accelerator, Hailo-8L, for frozen-backbone feature extraction during on-device training. The computational graph is partitioned so that the pre-trained backbone is quantized to INT8 and run on the accelerator, while only a lightweight FP32 classification head is fine-tuned on the host CPU, enabling frequent, energy-efficient in-field updates with most weights remaining fixed. Across multiple architectures and datasets, this pipeline achieves up to 15.4x faster wall-clock training time compared to a Raspberry Pi 5 CPU baseline, offers competitive throughput in favorable settings, and consistently reduces energy per sample. Post-training quantization restoration is shown to be crucial for preserving the quality of accelerator-generated features and mitigating accuracy loss in quantization-sensitive architectures. Overall, the results demonstrate a practical approach to efficient on-device adaptation using inference-oriented edge accelerators. The implementation is available at https://github.com/MatPiech/accelerator-training.

- **研究动机**：端侧设备（如智能手机、边缘设备、嵌入式系统）因计算能力、内存和功耗严重受限，无法支撑现代深度神经网络的端到端训练（反向传播）。然而，实现设备端模型适配（on-device adaptation）是实现终身个性化（lifelong personalization）和在线学习的关键，能减少网络依赖、保护隐私。
- **核心问题**：如何在不具备强大训练硬件的资源受限平台上，利用已有的商用推理加速器（设计初衷仅用于推理）来加速训练过程，使得模型能够在现场进行轻量的、频繁的、节能的更新。
- **整体含义**：提出一种异构计算范式——冻结骨干网络在INT8加速器上运行，仅微调FP32分类头在CPU上，从而在计算、功耗和精度之间取得实用平衡。这为边缘AI的终身学习提供了实际可行的路径。

## 2. 论文提出的方法论：核心思想、关键技术细节（公式/算法流程）
- **核心思想**：
  - **异构流水线执行**：将计算图分为两部分：
    - 预训练骨干网络（backbone）参数冻结，量化至INT8，部署在Hailo-8L加速器上执行前向传播（特征提取）。
    - 轻量级分类头（classification head）为FP32，在主机CPU上运行前向、损失计算、反向传播和参数更新。
  - **梯度流截断**：反向传播在加速器边界处截断，骨干网络不参与梯度计算和参数更新，仅分类头接收梯度更新。数学形式化：
    \[ f(x; \theta_b, \theta_h) = h(g(x; \theta_b); \theta_h) \]
    其中 \(g(\cdot; \theta_b)\) 为冻结的骨干，\(h(\cdot; \theta_h)\) 为可训练的头。
- **关键技术细节**：

## 6. 论文的主要结论与发现
1. **性能提升显著**：提议的异构流水线相比树莓派5 CPU，训练加速最高15.4×（ResNet18），且能耗降低3.3×（每样本）。在有利架构（如ResNet18）下甚至优于Jetson Orin Nano的吞吐量（6.04 vs 13.70 ms/sample）。
2. **架构敏感性**：加速倍数因架构而异——MobileNetV3 Large仅约4×加速，因其分类头计算量大，主机CPU成为瓶颈。FastViT-SA12虽加速约10×，但INT8量化导致较大精度损失。
3. **量化恢复策略的重要性**：
   - 对量化鲁棒架构（ResNet18, EfficientNet-Lite）低成本的Eq.或Eq.+IBC即可恢复精度。
   - 对敏感架构（MobileNetV3, FastViT）需更复杂的数据驱动方法（FT或AdaRound），但仍存在精度差距。
   - 建议：优先低成本策略，若精度不足再升级。
4. **小批量优势**：提议方案在小批量（1,4）时吞吐量优于Jetson Orin Nano，且功耗低，更适配资源受限场景。
5. **实用性**：证明了利用商用的推理加速器可以实现设备端训练，为边缘AI终身学习提供可行路径。
