## 摘要
集成片上神经处理单元（NPU）的微控制器已成为主流，但托管它们的系统软件尚未跟上：Zephyr或FreeRTOS与TensorFlow Lite Micro的生产组合将AI推理视为应用层库，使得内存碎片、加速器状态管理和模型生命周期防护成为应用开发者反复面临的问题。我们提出了SynapticOS第一阶段的基石——一个基于Zephyr构建的开源运行时，它将推理视为一等工作负载。它贡献了四个协同子系统：（1）一个张量感知的bump分配器，具有16字节DMA对齐的持久和短暂生命周期，共享单个arena，实现恒定时间分配（每次调用约154个周期，150 MHz下每秒约78,000次分配，与张量大小无关），且通过构造实现零碎片；（2）一个针对NPU和DSP的四状态硬件抽象层，由确定性软件存根（用于QEMU下的CI）和Neutron风格的后端（用于NXP MCXN947）实现；（3）一个三状态模型生命周期注册表，具有重复名称检测、幂等加载/卸载和热插拔防护；（4）一个四标记周期精确分析器。我们在NXP FRDM-MCXN947（双Cortex-M33，150 MHz）和qemu_cortex_m3模拟器上进行评估。构建占用为FRDM上67 KB闪存/184 KB SRAM（含shell，128 KB arena），QEMU上24 KB闪存/28 KB SRAM（无shell，8 KB arena）。通过确定性存根内核的端到端推理括号测量，对于16x16x3 INT8输入，FRDM上为1,038微秒，QEMU上为781微秒；这些是基线开销数字，并非Neutron硅片测量结果，后者将在第二阶段随真实SDK调用路径一起提供。在CI模拟器路径上，10个ZTEST测试套件中的61个测试在6.6秒内100%通过。SynapticOS在Apache 2.0许可下发布，网址为https://github.com/Dimitrios-Kafetzis/SynapticOS

## Abstract
Microcontrollers with on-die neural processing units (NPUs) have become mainstream, but the system software hosting them has not: production combinations of Zephyr or FreeRTOS with TensorFlow Lite Micro treat AI inference as an application-layer library, leaving memory fragmentation, accelerator-state hygiene, and model-lifecycle guards as recurring application-developer concerns. We present the Phase 1 foundation of SynapticOS, an open-source runtime built on Zephyr that treats inference as a first-class workload. It contributes four cooperating subsystems: (1) a tensor-aware bump allocator with 16-byte DMA-aligned persistent and ephemeral lifetimes sharing a single arena, achieving constant-time allocation (~154 cycles per call, ~78,000 allocations per second at 150 MHz, invariant across tensor sizes) with zero fragmentation by construction; (2) a four-state hardware abstraction layer for the NPU and DSP, implemented by a deterministic software stub (for CI under QEMU) and a Neutron-flavoured backend (for the NXP MCXN947); (3) a three-state model lifecycle registry with duplicate-name detection, idempotent load/unload, and hot-swap guards; and (4) a four-mark cycle-accurate profiler. We evaluate on the NXP FRDM-MCXN947 (dual Cortex-M33 at 150 MHz) and the qemu_cortex_m3 emulator. Build footprints are 67 KB flash / 184 KB SRAM on FRDM (shell, 128 KB arena) and 24 KB flash / 28 KB SRAM on QEMU (no shell, 8 KB arena). End-to-end inference brackets through the deterministic stub kernel measure 1,038 us on FRDM and 781 us on QEMU for a 16x16x3 INT8 input; these are baseline overhead numbers, not Neutron silicon measurements, which arrive with the real SDK invoke path in Phase 2. A 61-test suite across 10 ZTEST suites passes 100% in 6.6 s on the CI emulator path. SynapticOS is released under Apache 2.0 at https://github.com/Dimitrios-Kafetzis/SynapticOS

# SynapticOS 论文详细中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **问题**：微控制器（MCU）集成片上神经处理单元（NPU）已普及（如 NXP MCXN9 的 eIQ Neutron、Arm Ethos-U55），但系统软件（Zephyr、FreeRTOS）仍将 AI 推理视为**应用层库**（如 TensorFlow Lite Micro、CMSIS-NN）。这导致三个反复出现的应用开发者痛点：
  - **内存碎片**：通用堆混合管理模型权重（长期存活）和激活张量（每轮前向后丢弃），产生棋盘式碎片，限制可连续执行的推理次数。
  - **硬件抽象缺失**：不同 NPU（Neutron、Ethos-U）有不同的 SDK、异步完成约定和电源管理接口，应用层需自行适配。
  - **模型生命周期缺失**：模型状态（注册、加载、热交换、退役）未被运行时跟踪，易出现“加载中忙”、“交换时已加载”等滥用。
- **整体含义**：现有组合将系统级问题推给应用开发者，每个项目重复劳动。需要一种**推理优先**的运行时，将推理视为一类工作负载（workload-class concern），而非应用层库。

## 2. 论文方法论：核心思想、关键技术细节

### 核心思想
- 基于 Zephyr RTOS 构建 SynapticOS 运行时，将推理视为 **first-class workload**。
- 三个设计观察：
  1. 张量内存有两种生命周期（持久 vs 短暂），应分开管理。
  2. 加速器状态是状态机而非标志位，应集中暴露给所有上层模块。
  3. 确定性软件回退（stub）使 CI 测试无需真实 NPU。
- 第一阶段（Phase 1）聚焦**基础层**：内存、HAL、注册表、分析器、shell、测试基础设施。

### 关键技术细节

#### (1) 张量感知 bump 分配器（Tensor-Aware Bump Allocator）
- **布局**：单个连续 arena 分为持久区域（persistent，模型权重）和短暂区域（ephemeral，激活张量），外加独立 scratch 池。
- **算法**：两个 bump 指针均从基址向上增长；持久分配完后短暂分配紧随其后；scratch 池在 ephemeral reset 时一并重置。
- **对齐**：所有张量描述符和数据负载强制 16 字节 DMA 对齐（通过 `ALIGN_UP` 实现）。
- **API**：提供 `syn_mem_tensor_alloc`、`syn_mem_reset_ephemeral` 等；`syn_mem_tensor_free` 为 no-op（bump 分配器不支持单独释放）。
- **性能**：恒定时间 `O(1)` 分配（约 154 周期/次，与大小无关），零碎片（通过构造保证）。

#### (2) 四状态 NPU 硬件抽象层（HAL）
- **状态机**：IDLE → BUSY → SUSPENDED / ERROR，含前置条件守卫（如 BUSY 时加载返回 -EBUSY）。
- **双后端**：
  - **软件存根（stub）**：用于 QEMU CI，模型无关，计算输入字节和模类数，简单忙等待模拟延迟。确定性输出。
  - **NXP Neutron 后端**：用于 MCXN947，当前 Phase 1 仍使用相同存根逻辑（替换为真实 SDK 调用是 Phase 2 工作）。
- **选择机制**：链接时通过 CMake/Kconfig 选择，无运行时虚拟分派开销。

#### (3) 三状态模型生命周期注册表
- **状态转换**：UNREGISTERED → REGISTERED → LOADED，含幂等加载/卸载、重复名称检测、自动卸载后注销。
- **热交换**：`syn_model_swap` 在 Phase 1 仅做标志级簿记（真实 NPU 负载路径待 Phase 2）。
- **CRC 字段预留**：供 Phase 4 OTA 使用。

#### (4) 四标记周期精确分析器
- **标记点**：start、preprocess_done、npu_done、end，使用 `k_cycle_get_32()` 快照。
- **转换函数**：`k_cyc_to_us_ceil32` 得到微秒；`mark_end` 还捕获 arena 高水位和 NPU 利用率。
- **Phase 1 状态**：API 已实现且经单元测试，但推理路径未插入这些标记（计划 Phase 2 完成）。

#### (5) Zephyr Shell 前端
- 命令：`syn version`、`syn mem stats`、`syn model list`、`syn npu caps`、`syn npu state`、`syn prof last/enable/disable`。

## 6. 论文主要结论与发现

- **可行性**：基于 Zephyr 构建推理优先运行时是可行的，在资源受限 MCU 上（FRDM 67 KB flash，QEMU 24 KB flash）实现了小占用。
- **内存系统**：bump 分配器实现恒定时间（~154 周期/次）零碎片分配，支持持久/短暂分离，满足 16 字节 DMA 对齐需求。
- **硬件抽象**：双后端方案（软件存根 + Neutron）使 CI 与真实硬件共享同一接口，链接时选择无运行时开销。
- **模型生命周期**：三状态注册表提供幂等操作和防滥用保护，降低应用层开发复杂度。
- **延迟基线**：通过存根内核的端到端开销（FRDM 1,038 μs，QEMU 781 μs）为后续真实 NPU 路径提供了基准；真实 NPU 推理将低于此值（期望 tens of μs）。
- **测试可靠性**：61 个测试 100% 通过，CI 可重复，确定性存根保证了硬件无关的可复现性。

## 7. 优点

- **系统设计角度**：将内存管理、硬件抽象、生命周期集中到运行时，避免了应用层重复劳动，提供了干净的抽象边界。
- **技术亮点**：
  - 双生命周期 bump 分配器是简单的但有效的设计，解决了 MCU 推理中的碎片问题。
  - 双后端思路（软件存根 + 真实硬件）使 CI 成为可能，且无运行时开销。
  - 状态机 HAL 明确枚举加速器状态，避免了 SDK 碎片化导致的混乱。
- **测试充分性**：包含单元测试、性能基准、区域隔离验证、shell 交互验证。
- **开源与可复现**：代码、测试、日志全量公开（Apache 2.0），提供 QEMU 构建让任何人重复实验。
- **诚实性**：明确区分 Phase 1/2/3 进展，未夸大能力（如 Neutron 后端仍用存根、profiler 未接入、swap 仅标志级等）。

## 8. 不足与局限

- **真实 NPU 未启用**：Neutron 后端仅占位，未调用真实 SDK 执行实际推理；端到端延迟数字不代表硅片性能。
- **缺乏对比实验**：未与 TFLM 的现有分配器、k_malloc 等在碎片化场景下定量比较。
- **分析器未接入推理管道**：无法提供阶段分解（预处理/推理/后处理各占多少），导致延迟数据不完整。
- **单厂商验证**：仅 NXP MCXN947 实测；其他 NPU（Arm Ethos-U、ST X-CUBE-AI）后端未实现。
- **模型生命周期负载路径简化**：`syn_model_load` 仅在 `model_data` 非空时才调用 `syn_hal_npu_load_model`；示例仅注册元数据，未测试字节级加载。
- **DSP 部分未实现**：FFT 和 Q15 矩阵乘法返回 `-ENOTSUP`。
- **同步语义占位**：`supports_async = true` 但实际异步调用返回 `-ENOTSUP`（中断未布线）。
- **未评估长序列推理**：未演示连续多次推理对 arena 和往返时间的影响。
- **未考虑多模型或动态加载场景**：当前仅单个简单模型示例。
- **实时性分析有限**：仅测量平均分配时间，未分析最坏情况（虽然 bump 本身是常数，但日志/中断等其他因素未考虑）。
- **可移植性待验证**：虽然设计了小型 HAL 接口，但尚未移植到其他 RTOS（如 FreeRTOS）或硬件系列。
